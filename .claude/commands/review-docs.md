# ドキュメントレビュー

引数: ドキュメントパス（例: `/review-docs docs/design/proposals/P03-user-auth.md`）

## 手順

### ステップ1: 対象の確認

1. 指定されたドキュメントが存在するか確認する
2. プロファイルで **凍結指定された文書** が指定された場合は、更新禁止である
   ことを伝え、レビューしても修正は行えない旨を案内して確認を取る

### ステップ2: doc-reviewer サブエージェント起動

Task ツールで doc-reviewer サブエージェントを起動する:

- subagent_type: "doc-reviewer"（未登録の環境では general-purpose を使い、
  最初に `.claude/agents/doc-reviewer.md` と `report-protocol.md` を
  読むよう指示する）
- description: "Document detailed review"
- prompt: "[ドキュメントパス] を詳細にレビューしてください。まず CLAUDE.md の
  プロジェクトプロファイルを読んで規約と文書構成を把握し、以下の観点で
  評価してください:
  1. コード整合（ソースの実物と Grep で突き合わせる）
  2. 完全性（種別ごとの必須セクション）
  3. 一貫性（他文書・バックログとの整合）
  4. トレーサビリティ（要求仕様書の受け入れ条件 → 設計 → テストの対応）
  5. 実装可能性（設計書の場合。テスト観点の具体性・レイヤー配置）
  6. 規約準拠（強調前後の半角スペース・図の構文・日本語併記）
  レビューレポートを作成してください。"

### ステップ3: 結果の要約と対応

1. レビューレポートの要点をユーザーに報告する（[必須] / [推奨] / [提案] の順）
2. 修正の実施はユーザーの指示を待つ（このコマンドはレビューまで。
   修正まで指示された場合はマイクロコミットで対応する）

## 出力形式

```markdown
# ドキュメントレビュー結果: [ファイル名]

## 主な指摘
1. [必須] …（箇所と改善案）
2. [推奨] …
3. [提案] …

## 次のアクション
- （修正する場合の最優先対応）
```

## 注意事項

- サブエージェントは独立したコンテキストで動作するため、メインの
  コンテキストを消費しない（詳細な突き合わせはサブエージェント側で行う）
