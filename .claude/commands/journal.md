# 思考をジャーナルに残す（`/journal`）

**引数（任意）:**

| 形 | 何をするか |
|---|---|
| `/journal` | 直前の作業から 1 本書く（既定） |
| `/journal <題名や話題>` | 話題を指定して 1 本書く |
| `/journal commands` | 節目の操作（PR・マージ・ブランチ整理）を `commands.md` に足す |
| `/journal list` | `docs/journal/` の一覧を、日付・題名・学びの 1 行で出す |

`Skill('design-journal')` を規約の正とする。

## これは何のためのコマンドか

**目的は記録ではなく学習。** AI が出した結論ではなく、
結論に至る **道筋・外した仮説・捨てた選択肢** を、人が読んで真似できる形で残す。

成果物セットの 1 点ではない。書かなくてもスライスは完了する。

**このコマンドは手動の入口。** 合図が出た回は `/iterate` の中で
**既定 ON として自動的に書かれる** （聞かずに書き、ユーザーが
「今回は要らない」と言ったときだけ書かない）。
`/journal` は、それ以外の場面（自分で気づいて残したいとき・
過去の回を後から書きたいとき）で使う。

## 手順

### 1. 書く価値がある回か判定する（ここで止まってよい）

次のどれかに当たるときだけ書く。当たらなければ **書かずに終える**
（形骸化を防ぐことのほうが大事）。

- 判断点で選択肢を出した（`option-first` を使った）
- 詰まって抜けた（最初の見立てが外れた・2 回以上やり直した）
- 節目の操作をした（PR・マージ・ブランチ整理・設定の切り替え）

該当しないときは、そう告げて終了する。無理に書かない。

**選択肢を出した回は、追加の思考が要らない。** 提示した選択肢が
そのまま節 3（分岐図）に、選ばれなかった案と理由が節 4（外した仮説）に
なる。書き写して、実測のコマンド出力を足すだけ。

### 2. 追記で済まないか確かめる

`docs/journal/` を一覧し、同じ話題があればそのファイルに
日付見出しで追記する（新規に作らない）。

### 3. 雛形を写す

`.claude/skills/design-journal/template.md` を
`docs/journal/YYYYMMDD-<slug>.md` として写し、冒頭の HTML コメントを消す。

### 4. 節 1 から順に埋める

**節 0（結論）を先に書かない。** 観測 → 言い換え → 道筋 → 外した仮説 →
決めたこと → コマンド の順に書き、最後に結論を上へ足す。

- 観測とコマンド出力は **この会話で実際に得たもの** だけを貼る。
  手元に無ければ、その場で走らせて取り直す（推測で書かない）
- **節 4（外した仮説）を空にしない。** 空になるなら手順 1 の判定が誤り

### 5. 図を 1 枚描いて検証する

既定は判断の分岐図（`flowchart TD`。却下した枝を灰色で残す）。

```
powershell -File .claude/tools/check_mermaid_ids.ps1 -Path docs/journal/<file>.md
powershell -File .claude/tools/check_numbering.ps1 -Path docs/journal/<file>.md
powershell -File .claude/tools/check_diagrams.ps1 -Path docs/journal/<file>.md
```

上 2 つは即時。3 つ目は完全な構文検証で 1 ファイル約 5 秒なので、
書き終えたときに 1 回だけ走らせる。NG が出たまま終わらない。

### 6. 節目の操作なら `commands.md` にも足す

`.claude/skills/design-journal/git-commands.md`（操作の型）を先に読み、
**このプロジェクトで実際に打ったもの・詰まったもの** だけを
`docs/journal/commands.md` に「何をするか / 実際に打ったもの / 落とし穴」で足す。

### 7. コミットする

```
docs: ジャーナル「<題名>」を追加

- docs/journal/<日付>-<slug>.md
- 外した仮説: <1 行>
- 学び: <1 行>
```

## 完了後の報告（3 行）

```
書いた: docs/journal/<ファイル>（<題名>）
外した仮説: <1 行。ここが読みどころ>
次に同じ問題が来たら: <手順の 1 行目>
```

## やってはいけないこと

- 外した仮説を消す・行き来を一本道に整える（このコマンドの意味が消える）
- 打っていないコマンド・得ていない出力を貼る
- 毎反復で機械的に書く（合図が出た回だけ）
- **合図が出た回に「書きますか？」と聞く**（既定 ON なので聞かずに書く）
- 完了条件（`check_deliverables.py`）に足す
- 設計書の「判断の記録」の代わりにする
  （あちらは必須で読者は将来の実装者。こちらは既定 ON で読者はいま学ぶ人）
