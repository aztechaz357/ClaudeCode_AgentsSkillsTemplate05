# チケット駆動

**引数:** `status`（既定）/ `github` / `local` / `off` / `sync` /
`new <内容>` / `pull` / `close S##`

規約の正は `.claude/skills/issue-tracking/SKILL.md` 。
**進捗の正は `docs/backlog.md` のまま** で、チケットはその写し（窓）です。
**既定は `github`** —— チケット駆動そのものは既定で有効で、
`local` / `off` は置き場所を変える選択です。

## 最初に必ずやること（全モード共通）

```
<ツール実行コマンド> .claude/tools/issue_mode.py
```

終了コードで分岐する（会話の記憶で判断しない）:

| 終了コード | 意味 | やること |
|---|---|---|
| 0 | `使用: github` | 依頼どおり進む（`gh` を使う） |
| 3 | `使用: local` | 依頼どおり進む（ハブの `## チケット` 節を使う。 **`gh` を呼ばない** ） |
| 1 | `使用: off` | 切り替え以外の引数なら「off です」と 1 行返して終了 |
| 2 | 節が無い / 値が不正 | 推測で有効にせず、`/issue github` `/issue local` を案内して終了 |

**`0 以外 = 使わない` と読まない。** `3` は「ローカルで使う」であって
「使わない」ではない（この読み違いだけでローカル起票が全部飛ぶ）。

## モード: `status`（引数なしのとき）

1. `issue_mode.py` で設定を読む
2. `github` / `local` なら差分を出す（書き込まない）:

   ```
   <ツール実行コマンド> .claude/tools/sync_issues.py
   ```

3. 3 行で報告する:

   ```
   チケット追跡: {github / local / off}（リポジトリ: {owner/repo または なし}）
   差分: 起票 {n} / 更新 {n} / 完了 {n}（github では 作成 / 更新 / 取り込み候補）
   次: {/issue sync（差分がある） / なし（同期済み）}
   ```

`off` のときは 1 行目だけを返し、`/issue github` `/issue local` を添える。

## モード: `github`（既定。使い始める・ローカルから移る）

1. `gh auth status` と `gh repo view --json nameWithOwner` で
   **認証とリポジトリを確認する** 。どちらかが失敗したら **ここで止める** 。
   認証情報は自分で入力しない（ユーザーに `gh auth login` を案内する）。
   リモートが無いなら **`/issue local` への切り替えを提案して終了する**
   （黙って local に落とさない）
2. 設定を書き換える:

   ```
   <ツール実行コマンド> .claude/tools/issue_mode.py --set github --repo <owner/repo>
   ```

3. ラベルを確認する（`gh label list`）。規約のラベル
   （`slice` / `debt` / `L1` / `L2` / `L3`）に無いものがあれば、
   **作成してよいかユーザーに確認してから** `gh label create` する
4. 差分を出す（`sync_issues.py`。送信しない）
5. 「何本作るか」を提示し、承認を得てから `/issue sync` へ進むよう案内する
   （このコマンドでは作成まで行わない）
6. **ローカルから移ってきたなら、ハブの `## チケット` 節を消さない** ——
   履歴はそこにしか無い。状態欄に「GitHub へ移行（#<番号>）」を 1 行足す

既に L3 のスライスは既定では Issue にしない。履歴として残したいときだけ
`sync_issues.py --include-done` を使う（作った直後に閉じる）。

## モード: `local`（GitHub を使わずチケットで進める）

1. `github` から移るなら、開いている Issue を数える
   （`gh issue list --state open`）。1 本以上あれば移行コメントを
   付けてよいか確認する（下の `off` と同じ文面。 **閉じない・消さない** ）
2. 設定を書き換える:

   ```
   <ツール実行コマンド> .claude/tools/issue_mode.py --set local
   ```

3. 差分を出す（`sync_issues.py`。書き込まない）。
   **ハブが無いスライスは「ハブが無い」と報告される** ——
   先に `Skill('slice-definition')` でハブを作る（チケットはハブの節なので、
   ハブより先にチケットは作れない）
4. 「何本起票するか」を提示し、承認を得てから `--apply` する
5. 以後、 **どのエージェントも `gh` を 1 回も呼ばない** ことを 1 行で報告する

## モード: `off`（チケットをやめる）

1. `github` だったなら開いている Issue を数える（`gh issue list --state open`）
2. 1 本以上あれば、停止コメントを付けてよいか確認する:

   > このリポジトリはチケット追跡を停止しました。
   > 進捗は `docs/backlog.md` を参照してください。

   承認が得られたら `gh issue comment` で付ける。 **閉じない・消さない**
3. 設定を書き換える:

   ```
   <ツール実行コマンド> .claude/tools/issue_mode.py --set off
   ```

4. 「以後どのエージェントも `gh issue` を呼ばず、ハブに `## チケット` 節を
   作らない」ことを 1 行で報告する。 **既にあるチケット節は消さない**

## モード: `sync`（バックログ → チケット）

`Task(issue-manager)` を起動する。プロンプトに次を必ず書く:

- 依頼: `docs/backlog.md` とチケットの差分を同期する
- **現在のモード**（`github` / `local`。`issue_mode.py` の終了コードで確かめた値）
- **承認なしで `--apply` を実行しないこと**
- 差分は「起票 {n} / 更新 {n} / 完了 {n}」の形で先に提示すること

差分の提示を受けたら、ユーザーに確認してから適用させる。

## モード: `new <内容>`

**バックログを先に更新する** （正はバックログ。Issue から作らない）。

1. `/backlog <内容>` と同じ判定でスライス表か負債表に行を足す
   （ゴールに寄与しないなら「今回のゴールの外」表へ。Issue は作らない）
2. コミットする（接頭辞 `docs:`）
3. `/issue sync` に進む（新しい行が Issue になる）

「Issue だけ作ってバックログに載せない」は行わない —— 正が 2 つになる。

## モード: `pull`（外部起票の取り込み。`github` のときだけ）

`local` / `off` では外から来る口が無いので「このモードでは使えない」と
1 行返して終了する。`Task(issue-manager)` を起動する。
判定基準は `docs/concept.md` のゴール。

1. タイトルが `S##:` / `D##:` で始まらない open Issue を集める
2. 1 本ずつ「寄与する / しない」を判定してバックログへ振り分ける
3. 取り込んだものはタイトルに接頭辞を付けて対応付ける
4. **判定に迷ったものは勝手に決めず、一覧にしてユーザーへ提示する**

## モード: `close S##`

**L3 に到達したスライスだけ閉じる。** `docs/backlog.md` の成熟度を読み、
L3 未満なら閉じずに理由を返す（規約: L1・L2 は完了ではない）。
`local` では「閉じる」= チケット節の状態を `完了` にすること
（ハブもチケット節も **消さない** ）。

## チケットを使わないと決めているとき

`/issue off` を実行したときだけ、
**このコマンド以外はチケットに一切触れません** （`/iterate` も `/status` も
挙動が変わらない）。既定は `github` なので、 **何もしないと Issue 駆動になります** 。

## やってはいけないこと

- 承認なしで `gh issue create` / `edit` / `close` / `comment` を実行する
- 承認なしで `sync_issues.py --apply` を実行する（`local` でもハブを書き換える）
- チケットに進捗を書いてバックログを更新しない（正が 2 つになる）
- `使用: off` のまま `gh issue` を呼ぶ
- **`使用: local` のまま `gh` を呼ぶ**（終了コード 3 を 0 と同じに扱わない）
- **`github` で `gh` が使えないときに黙って `local` に落とす**（止まって提案する）
- ローカルチケットの履歴を書き換える・消す
- L1・L2 のスライスのチケットを閉じる
- 反復の段ごとにチケットを切る（チケット 1 本 = バックログ 1 行）
