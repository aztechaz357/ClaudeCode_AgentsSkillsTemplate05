# 追いつく（差分ダイジェスト）

**引数（任意）:** 起点の ref（例: `/catchup a20ebed`、`/catchup HEAD~10`）。
省略時は `.steering/last-reviewed`（無ければ直近 20 コミット）。

規約の正は `.claude/skills/catchup/SKILL.md` 。
**全部を読まず、後から変えにくいものだけを読む** ための入口です。

## 手順

1. ダイジェストを機械的に作る（推測で書かない）:

   ```
   <ツール実行コマンド> .claude/tools/build_digest.py
   ```

   終了コード: 0 = 未読なし（ここで終了してよい）/ 1 = 未読あり / 2 = エラー

2. **主張の差分を出す**（正しさを判断するための本体。散文より先に見る）:

   ```
   <ツール実行コマンド> .claude/tools/build_claims.py --diff
   ```

   終了コード: 0 = 変化なし / 1 = 変化あり / 2 = エラー。
   **「弱まった保証（`⊢` → `⊬`）」と「消えた保証」を最優先で見る** ——
   この 2 つは散文の差分では絶対に気づけない後退で、
   行が増えたことには気づけても保証が減ったことには気づけない。
   規約は `Skill('verifiable-claims')`

3. ツールが「影響度 高」に挙げた文書を **実際に Read する**
   （最大 3 件。ADR → 設計書の「判断の記録」→ 要求の理由 の順）

4. 読んだ内容から **1 件 1 行** の要約を書く。
   **ツールの出力だけで要約を書かない** —— 見出しから中身は推測できない

5. 下の形で報告する

6. ユーザーが「追いついた」と言ったら既読地点を進める（ **2 つとも** ）:

   ```
   <ツール実行コマンド> .claude/tools/build_digest.py --mark
   <ツール実行コマンド> .claude/tools/build_claims.py --mark
   ```

   **報告より先に `--mark` しない**（読んでいないものが既読になる）

## 報告の形（10 行以内）

```
未読: {n} コミット（{短縮ハッシュ} → {短縮ハッシュ}・{日付} 〜 {日付}）

保証の変化: 弱まった {n} / 消えた {n} / 追加 {n}（未証明のまま {n}）
  ⊬ {S##.Q#} {式}   ← 弱まった・消えたものだけ 1 行ずつ

後戻りが高い判断 {n} 件
  {ADR/設計/要求/規約} {1 行要約}  —— {パス}
  ...

その他: 実装 {n} 件 / テスト {n} 件 / 文書 {n} 件
負債: 増 {n} 件 / 返 {n} 件   成熟度: {S## L0 → L1 など}

次に読むなら: {パス}（{なぜそこか 1 行}）
```

未読が 0 なら 1 行で「追いついています（HEAD: …）」と返す。

## 判断が必要なものを見つけたとき

ダイジェストは **承認の場ではない** 。ただし次を見つけたら報告に 1 行足す:

- 仕様と実装の矛盾 → 絶対ルール 3。 **その場で直さずユーザーに確認する**
- 記録されていない手抜き → 負債表に無い仮実装。`/backlog` で記録を促す
- ADR と実装の不一致 → どちらが正かをユーザーに確認する

## やってはいけないこと

- 実装の差分から読み始める（「なぜ」が分からず時間だけ溶ける）
- ダイジェストの見出しだけで中身を要約する（推測は嘘になる）
- 報告前に `--mark` する
- `/catchup` の中で修正・実装を始める（読む工程と直す工程を混ぜない）
