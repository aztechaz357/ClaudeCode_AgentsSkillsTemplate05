# 反復を 1 回回す（既定の開発サイクル）

**引数（任意）:** スライス番号または内容（例: `/iterate S03`、
`/iterate CSVのフィルタ`）。省略時は `docs/backlog.md` の最上段を取る。

**1 回の反復で上げるのは成熟度 1 段だけ。** L0 → L1、または L1 → L2。
2 段まとめて上げない（それが「完璧の積み上げ」の始まり）。
目安は **半日以内** 。超えたらスライスが大きすぎる。

## 実行方針

**原則としてユーザーの介入なしに完了まで進む。** 停止するのは次の 3 つだけ:

1. **不可逆な操作を含む** ことが判明した（削除・課金・外部送信）→
   厚い経路（`/add-feature`）へ切り替える判断をユーザーに確認する
2. **ゴールの外** の実装が必要になった（`docs/concept.md` の非目標に触る）
3. **3 回作り直しても L1 に到達しない** （設計不足。設計に戻る判断が必要）

**停止しない**（自分で決めて記録して進む）もの:

- 層の分け方・命名・ファイル配置 → `Skill('layered-architecture')` に従い決める
- 仮実装で済ませるかどうか → L1 なら仮実装で進め、負債に記録する
- 仕様の細部 → L1 は正常系だけ。境界値は L2 の反復に回す

`.steering/local-mode.md` が存在する場合は無停止で実行せず、
`.claude/local-llm/policy.md` に従いステップごとに停止して報告する。

## 前提

- 骨組みが通っていること（`docs/backlog.md` の「骨組み」が `通った`）。
  通っていなければ **このコマンドを実行せず `/skeleton` を案内する**
- 着手中のスライスが無いこと（WIP = 1）。あればそれを先に終わらせる

## ステップ0: 選ぶ（1 本だけ）

1. `docs/backlog.md` を読む
2. 引数が無ければ `maturity.md` の PM ルールで対象と目標レベルを決める:
   - L0 のスライスが残っている → 最上段の L0 を L1 へ
   - 全スライスが L1 → 価値の高い順に L2 へ
   - 負債が反復 2 回分たまっている → **`/refactor` を先に案内して終了する**
3. 対象と目標レベルを宣言する（例: `S03 を L0 → L1`）
4. バックログの「いま着手中」を更新する

## ステップ1: 薄く決める

`Skill('slice-definition')` で要求（`docs/usdm/src/S##-<name>.html`）と
スライス文書（`docs/slices/S##-<name>.md`）を書く。
**分量の上限を守る** （超えたらスライスを分割する）。

| 目標 | 書くもの | 上限 |
|---|---|---|
| L0 → L1 | 要求＋ **理由** ＋ 仕様（正常系）＋ 薄い設計 | 要求 1・理由 1 行・仕様 3 条 ＋ 設計 5 行 |
| L1 → L2 | 同じ要求の仕様に境界値・失敗経路を追記 | 制限なし（ここは網羅する） |

記法は `Skill('usdm')` が正（要求は HTML の表、「〜したい」、
 **理由は必須** 、仕様番号は `<要求番号>-<連番>`）。
書いたら次を実行して違反 0 件を確認する:

```
<ツール実行コマンド> .claude/tools/build_usdm.py
```

厚い経路が必要か判定する（`agile-process` の「いつ厚く書くか」）。
該当したら停止例外 1 としてユーザーに確認する。

図・クラス図・シーケンス図は **書かない** 。必要になるのは L3 の
`docs/design.md` だけ。ここで作図に入ると反復が止まる。

## ステップ2: TDD で実装する

`Skill('development-guidelines')` の規約に従い、テスト先行で進める。
コンテキストを節約したい場合は `tdd-implementer` に委譲する
（プロンプトに **目標成熟度** と steering パスを必ず含める）。

1. テストを書く（docstring 4 項目必須）
2. プロファイルの範囲指定テストコマンドで **Red を確認** する
3. 目標レベルの許容範囲で実装する:
   - **L1**: 仮実装・ハードコード・1 ファイル集約・層の逆流すべて可
   - **L2**: 仮実装を消す。想定内の失敗は結果値で返す
4. プロファイルの全体テストコマンドで全緑を確認する
5. コミットする（接頭辞 `実装:`。差分 20〜30 行を超える前に区切る）

Red が確保できなかったテストは、変異テストで有効性を確認する:

```
<ツール実行コマンド> .claude/tools/mutate.py --file <実装> --find <正> --replace <誤> --expect <テスト名>
```

（前置コマンドはプロファイルの「`.claude/tools/` の Python ツール実行」。
SURVIVED が出たらテストの穴なので、テストを足してから進む）

## ステップ3: 通す（E2E の確認）

**このステップを飛ばさない。** 反復ごとに完走できることを確かめるのが、
このプロセスの背骨。

1. プロファイルの統合テストコマンドで **既存の E2E を含めて** 実行する
   （骨組みの E2E が赤くなったら、それは回帰。直してから進む）
2. 目標が L1 なら、このスライスの仕様に対応する E2E を 1 本足す
3. 目標が L2 なら、仕様 1 条につきテスト 1 本以上にする
   （`integration-tester` に委譲可）
4. プロファイルの動作確認コマンドで実物を動かし、出力を得る

## ステップ4: 検証（成熟度 1 段だけ）

`implementation-validator` を起動する。プロンプトに
**「対象は S##、現在 L{n}、目標 L{n+1}。maturity.md の目標レベルの列だけで
判定してください」** を明記する。

- 目標レベルの [必須] があれば直して再検証する
- **上のレベルの指摘は負債候補として受け取り、不合格の理由にしない**
  （負債表に追記して進む）

安全機構に触れた場合のみ `security-checker` を併走させる。

## ステップ5: 記録する

1. スライス文書を更新する:
   - 「成熟度」を目標レベルに
   - 「実績」に **実際の出力** を貼る（推測禁止・絶対ルール 7）
   - 「残した手抜き」を埋める（L2 に上げたなら、消した行に `済` を付ける）
2. 要求 HTML を更新する:
   - 緑になったテストに対応する仕様の検証欄を `□` → `☑` に変える
   - 成熟度バッジ（`span.maturity`）を目標レベルに
3. `docs/backlog.md` を更新する:
   - 成熟度列と「次の一手」列
   - 負債表へ新しい手抜きを転記（`D##` 採番・痛み・返す条件）
   - 「いま着手中」を `なし` に戻す
4. **要求一覧を再生成する**
   （`<ツール実行コマンド> .claude/tools/build_usdm.py`。
   `index.html` は gitignore 対象なのでコミットには入らない）
5. コミットする（接頭辞 `docs:`）

## ステップ6: 次の一手を決める

`maturity.md` の PM ルールに機械的に当てはめ、 **1 つだけ** 提示する。

- 負債が反復 2 回分たまった → `/refactor`
- L0 が残っている → `/iterate`（次のスライス）
- 全スライスが L1 → `/iterate`（L2 へ）
- 全スライスが L2 で渡す予定がない → **完成** 。次のゴールを提案する

## 完了条件

- [ ] 対象スライスが目標レベルの完了条件（`maturity.md` の該当列）を満たす
- [ ] 全テストが緑（骨組みの E2E を含む。passed / skipped を報告に含める）
- [ ] 実物を動かした出力がスライス文書に貼られている
- [ ] 残した手抜きが負債表に記録されている
- [ ] **USDM 違反 0 件**（`build_usdm.py` が終了コード 0）
- [ ] `docs/backlog.md` の成熟度・着手中・次の一手が更新済み
- [ ] 未コミットの変更が残っていない

## やってはいけないこと

- 2 段まとめて上げる（L0 → L2）
- 目標が L1 のときに境界値・失敗経路・層の分離・文書整備をやる
- 手抜きを記録せずに残す
- 骨組みの E2E が赤いまま次へ進む
- 着手中のスライスを残して別のスライスに移る
