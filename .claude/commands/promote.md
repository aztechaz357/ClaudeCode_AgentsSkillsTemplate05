# 工房から反復開発レーンへ昇格させる

引数: ツール名とスライス番号（例: `/promote csv-diff S07`。番号を省略した場合は
`docs/backlog.md` の次番号を採番する）

工房レーン（`workshop/tools/<name>/`）で育ったツールを、
反復開発レーン（バックログ → スライス → TDD → E2E）へ移す。

**このコマンドは昇格の判断と入力の準備までを行う。**
実装そのものは `/iterate S##`（または該当する場合のみ `/add-feature S##`）が
引き受ける。

## ステップ1: 昇格が妥当か検証する

`workshop` スキルの「昇格の判断」に照らす。次のどれかに当てはまること。

| 該当条件 | 反復開発レーンで得られるもの |
|---|---|
| 他のツールから使いたくなった | 呼び出せる形への整理と回帰テスト |
| 1 ファイルに収まらなくなった | 層への分割（L2 以降） |
| 自分以外が使う | 受け入れ条件・E2E・マニュアル（L3） |
| 壊れると困る | 逆流の機械検証と回帰テスト |
| 設定・状態を持ち始めた | infrastructure への隔離 |

**どれにも当てはまらない場合は昇格させない。** その旨をユーザーに伝え、
工房に置いたままにすることを提案する（全部を上げると工房の速度が死ぬ）。

また、対象が **開発プロセス自体を機械化する道具** （検証・生成スクリプト）
だった場合は、反復開発レーンではなく `.claude/tools/` が行き先。
`tool-authoring` スキルを案内して終了する。

## ステップ2: 現状を棚卸しする

対象ツールの `README.md`・実装・テストを読み、次を書き出す:

- 現在できること（実行例と実出力。README に貼ってあるもの）
- 現在できないこと（README の「既知の制限」）
- 踏んだ落とし穴（README の「落とし穴」表）
- 既存テストのケース一覧

**これがスライス文書の材料になる。** 工房で貯めた実運用の知見が
そのまま受け入れ条件と境界値になるので、捨てない。

## ステップ3: 昇格後の成熟度を決める

工房ツールは **すでに動いている** 。したがって昇格直後の成熟度は
通常 `L1 動く` 相当から始まる（ゼロからではない）。

| 工房での状態 | 昇格後の出発点 | 次の一手 |
|---|---|---|
| 実行例があり、テストが通っている | `L1 動く` | `/iterate` で L2 へ（境界値・失敗経路） |
| 落とし穴表が埋まっており、失敗経路も検証済み | `L2 固い` 相当 | `/refactor` で L3 へ（渡すなら） |
| 不可逆な操作・外部公開・秘密情報を扱う | —— | `/add-feature` の厚い経路で書き直す |

## ステップ4: スライス文書の入力を作る

`slice-definition` スキルに渡す形で、ステップ2 を整理する。

- README の実行例 → **L1 の受け入れ条件**（入力 → 観測結果の形に直す）
- 「落とし穴」表の各行 → **L2 の受け入れ条件**（失敗経路）
- 「既知の制限」 → **非目標** または別スライス送り
- 既存テストのケース → E2E へ翻訳する候補
- **工房の実装のうち、そのまま持ち込めない部分** → 負債表の初期行

ここまでをユーザーに示し、スライスの範囲と出発レベルについて確認を取る。

## ステップ5: 工房側に昇格の跡を残す

**工房のディレクトリは削除しない。** 次の 2 点だけ変更する。

1. `README.md` の front matter を `status: promoted` にし、`updated` を今日に
2. `README.md` の本文先頭に、昇格先（`docs/slices/S##-*.md` と
   本実装のパス）へのリンクを 1 行足す

```
powershell -File .claude/tools/index_workshop.ps1
```

跡を残すのは、半年後に「これはどこへ行ったのか」を辿れるようにするため。

## ステップ6: バックログへ載せて引き渡す

1. `docs/backlog.md` のスライス表に S## の行を追加する
   （成熟度はステップ3 で決めた出発点。価値と依存も書く）
2. ステップ4 で作った材料をスライス文書の初期内容として書く
3. `/iterate S##` を案内する（ユーザーの指示があればそのまま起動する）

工房の実装コードは **そのまま移植してもよい** （動いているものを捨てない）。
ただし移植したコードは L1 相当として扱い、テストが無い部分には
**先にテストを足す** （テスト先行は絶対ルール 5。成熟度に関係なく必須）。

## ステップ7: コミット

```
docs: <name> を S## へ昇格（工房 → 反復開発レーン）

- workshop/tools/<name>/README.md を status: promoted に更新し昇格先へのリンクを追加
- 昇格の根拠: <該当した条件>
- docs/backlog.md に S## を追加（出発レベル: L1）
- docs/slices/S##-<name>.md に受け入れ条件と薄い設計を記載
- 負債表に <n> 件を登録（工房から持ち込む手抜き）
- CATALOG.md を再生成
```
