# 記入用ワークシート（`/intake`）

**引数（任意）:**

| 形 | 何をするか |
|---|---|
| `/intake` | 記入済みのワークシートを **回収して深掘りする**（既定） |
| `/intake 要求` | 段1（要求）のワークシートだけを対象にする |
| `/intake 設計` | 段2（設計）のワークシートだけを対象にする |
| `/intake 作る` | ワークシートを今すぐ用意する（反復の外からでも） |

`Skill('intake')` を規約の正とする。

## これは何のためのコマンドか

**「何を作るか」と「なぜ要るか」は、ユーザーの中にしかない。**
CLI の選択肢は速いが、理由・非目標・懸念のような長いものは拾えない。
このコマンドは、それを **エディタで書いてもらう** ための入口。

**Claude は用紙を作り、深掘りするだけで、中身は書かない。**

## 手順

### 1. 対象のワークシートを探す

```
.steering/<最新の反復ディレクトリ>/intake/S##-要求.md
.steering/<最新の反復ディレクトリ>/intake/S##-設計.md
```

- 反復ディレクトリが無い → まだ反復が始まっていない。
  `/iterate` を先に打つよう案内して終える（勝手に作らない）
- ワークシートが無い → `作る` として扱う（下の 2 へ）
- 先頭に `> **取り込み済み**` がある → **もう死んだ用紙** 。
  再取り込みしない。新しく作るか聞く

### 2. `作る` のとき

`.claude/skills/intake/template-requirement.md` または
`template-design.md` をコピーして、`S##` と機能名だけを埋める。
**中身の欄は埋めない**（埋めた時点でこの仕組みの意味が消える）。

置いたら、パスと「埋め終わったら `/intake` と打ってください」を出して
**そこで待つ** 。待っている間に要求仕様書を書き始めない。

### 3. 回収して読む

ワークシートを読み、次の 3 つを分けて把握する。

| 種類 | 扱い |
|---|---|
| **埋まっている** | そのまま採用する。 **言い換えて要約しない** |
| **空欄** | 候補を 2〜3 個出して選ばせる（白紙のまま聞き返さない） |
| **曖昧**（「適切に」「ちゃんと」） | 観測できる形に落とす問いを出す |

### 4. 深掘りする（1 往復で 3 点まで）

`Skill('intake')` の「深掘りの仕方」の表に従う。優先順位はこの順。

1. **異常系（`E1`）が空** —— 最も重い穴。ここが埋まるまで先へ進まない
2. **理由が空、または要求の言い換え** —— 以降の成果物が全部推測に乗る
3. **入出力が空** —— 作るものの形が決まらない
4. その他の空欄・曖昧・矛盾

**4 点以上指摘しない。** 添削になり、書く側が受け身になる。
`AskUserQuestion` を使うときは `Skill('option-first')` の形
（推奨を先頭・ **選ばないとどうなるか** を各案に）。

応答が無ければ **推奨で進み** 、選択肢ごと記録に残す（待ち続けない）。

### 5. 正式文書へ落とす

| ワークシート | 落とす先 |
|---|---|
| 要求・理由・非目標 | `docs/usdm/src/S##-*.html`（要求行・理由行・説明行） |
| 入出力・`N1`・`E1` | 同 HTML の入出力表と例の表 |
| 完走の条件 | 同 HTML の仕様行 |
| 層・契約・データの持ち方 | `docs/design/S##-*.md` の構成と図 |
| 迷い・却下案 | 同設計書の「判断の記録」 |
| 手抜き・懸念 | `docs/backlog.md` の負債表 |

**理由はユーザーの言葉のまま残す。** 事実（回数・時間・失敗した経験）を
落とさない。整えるのは語尾までにする。

### 6. ワークシートを閉じる

落とし切ったら、ワークシートの先頭に 1 行足す。

```markdown
> **取り込み済み**（YYYY-MM-DD）—— 正は docs/ 側。この用紙は編集しない。
```

以降このファイルは読まない・書かない（正が 2 か所になるとドリフトする）。

### 7. 検証してコミットする

```
<ツール実行コマンド> .claude/tools/build_usdm.py
<ツール実行コマンド> .claude/tools/check_deliverables.py --slice S##
```

コミット接頭辞は落とした先に合わせる（`要求:` または `設計:`）。
ワークシート自体は `.steering/` 配下なのでコミットされない。

## やってはいけないこと

- **ワークシートの空欄を Claude が埋める**（特に理由と異常系）
- 打たれる前に読みに行く（書きかけへの指摘は、書く気を折る）
- 取り込み済みの用紙を読み直す・更新する
- ワークシートを `docs/` に置く（成果物ではない）
- 1 往復で 4 点以上指摘する
- ユーザーの記入を待ち続けて反復を止める（推奨で進み、記録する）
