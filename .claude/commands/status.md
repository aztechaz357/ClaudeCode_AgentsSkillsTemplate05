# 現在地を 1 枚にする

**引数:** なし。

エージェントに任せて進めていると、ユーザーが大枠を見失う。
このコマンドは **会話を追わなくても現在地が分かる 1 枚** を作り直す。

## 実行すること

1. 記録を最新にしてから描く（古い記録を描いても意味がない）:

   ```
   <ツール実行コマンド> .claude/tools/build_usdm.py
   <ツール実行コマンド> .claude/tools/check_deliverables.py
   <ツール実行コマンド> .claude/tools/build_structure.py
   <ツール実行コマンド> .claude/tools/build_claims.py
   <ツール実行コマンド> .claude/tools/build_status.py
   ```

   `check_deliverables.py` と `build_claims.py` が 1 を返しても
   **止まらない** （欠けていること・未証明が残っていることこそ
   見せたい情報なので、そのまま 1 枚に載る）。
   前置コマンドはプロファイルの「`.claude/tools/` の Python ツール実行」。

2. 生成された `docs/status.html` のパスをユーザーに伝える
   （`file://` でそのまま開ける自己完結 HTML）

3. **同じ内容を 5 行でも書く** （HTML を開かなくても分かるように）:

   ```
   ゴール: {docs/concept.md の一行}
   到達:   L3 {n}本 / L2 {n}本 / L1 {n}本 / L0 {n}本（全 {N} 本）
   一式:   {n}/{n} 本がそろっている（欠けは S##: {何が}）
   主張:   ⊢ {n} / ⊬ {n}（未証明は S##: {どれ}）
   負債:   {n} 件（痛み高 {n} 件）
   次の一手: {1 つだけ}
   ```

   **主張の行が「正しさ」の唯一の要約** 。`⊬` は「主張しているが
   未証明」であり、そのまま負債（規約: `Skill('verifiable-claims')`）。
   台帳を文書として保存しない —— 正は各設計書の「## 主張（契約式）」。

## 読み方（ユーザー向けの案内）

| 見るところ | 何が分かるか |
|---|---|
| 上の帯 | ゴールまでの距離。灰色（L0）が多いなら、まだ骨組みに近い |
| 充足マトリクス | どのスライスのどの成果物が欠けているか。⬜ が残っていたら未完了 |
| **主張（契約式）** | **正しさが保証されているか** 。⊬ が先頭に並ぶ。充足マトリクスが全部 ✅ でも ⊬ だらけなら「そろっているが何も証明されていない」 |
| 負債表 | 痛み 高 が 3 件以上あれば、次は `/refactor` |
| 直近の作業 | コミットと、役割エージェントが残したレポート |

## 注意

- このコマンドは **何も書き換えない** （生成物を作るだけ）。
  記録の修正が必要なら `/check-docs` を案内する
- `docs/status.html` は生成物。gitignore 対象なのでコミットに入れない
- バックログが無い段階では動かない → `/backlog init` を案内する
