# 負債を返す（きれいにする工程）

**引数（任意）:** 負債番号・スライス番号・対象範囲
（例: `/refactor D02`、`/refactor S03`、`/refactor 層の逆流`）。
省略時は `docs/backlog.md` の負債表から返す順序で上位を取る。

手順の正は `Skill('refactoring')` 。 **振る舞いを変えない** ことが絶対条件。

## 実行方針

原則としてユーザーの介入なしに進む。停止するのは次の 2 つだけ:

1. **テストの期待値を変えたくなった** → それはリファクタリングではない。
   仕様変更なのでユーザーに確認する
2. **返すのに機能追加・バグ修正が必要** → 混ぜない。バックログに積み、
   このリファクタリングの範囲から外す

## ステップ0: 着手前の確認（省略禁止）

1. `git status` が clean であることを確認する（未コミットがあれば先に片付ける）
2. プロファイルの全体テストコマンドを実行し、 **全緑と件数** を記録する。
   これが終了時に一致すべき **基準値**
3. **赤があれば着手しない** 。直すのが先（赤いままの整理は結果を判定できない）

## ステップ1: 返す負債を選ぶ

`docs/backlog.md` の負債表から、`refactoring` スキルの順序で選ぶ:

1. 痛み **高**
2. 「返す条件」が満たされたもの
3. 同じ手抜きが 2 か所以上に増えたもの
4. 痛み 中 で、これから触る場所にあるもの

**1 回で返すのは上位数件まで。** 全部返すまで止めないと反復が止まる。
返さないと決めた負債は状態を `見送り（YYYY-MM-DD・理由）` にする。

範囲が広いときは `impact-analyzer` に影響範囲を調べさせる
（多数ファイルの読み込みを親のコンテキストに載せない）。

## ステップ2: 安全網を確認する

返す範囲を覆うテストがあるか確認する。

- **無ければ先にテストを足す** 。テストを足すコミットと整理するコミットは分ける
- 足すテストは「現在の振る舞い」を固定するもの（仕様を直さない）

## ステップ3: 1 手ずつ返す

`refactorer` エージェントに委譲するか、自分で実行する。
どちらの場合も **1 手 = 1 種類の変換 × 1 コミット** 。

変換の種類（混ぜない）: 名前を変える / 抽出する / 移す /
重複を統合する / 契約を切る / 仮実装を本実装に置き換える

各手のあとに必ず:

1. プロファイルの全体テストコマンドで全緑を確認する
2. コミットする（接頭辞 `整理:`。本文に「何を・どこへ・なぜ」）

まとめてやって最後にテストするのは禁止（壊した箇所を特定できなくなる）。

## ステップ4: 層の検証

層をまたぐ移動をした場合、プロファイルの「アーキテクチャテスト」で
**逆流ゼロ** を確認する。未整備なら `dependency-checker` に
`Skill('layered-architecture')` の 1 ルール（逆流禁止・循環禁止）で
確認させ、機械検証の新設を提案する。

## ステップ5: 検証

- [ ] テスト件数が基準値と **同数** で全緑
      （減っていたらテストを消している。増えていたら機能を混ぜている）
- [ ] プロファイルの動作確認コマンドで実物が動き、出力が以前と同じ
- [ ] lint / typecheck がプロファイルに定義されていれば緑

## ステップ6: 記録する

1. `docs/backlog.md` の負債表:
   - 返した行の状態を `済（コミットハッシュ）` にする（ **行は消さない** ）
   - 見送った行を `見送り（日付・理由）` にする
   - 作業中に見つけた新しい負債を追記する
2. 対象スライス文書の「残した手抜き」にも `済` を付ける
3. スライスが L3 の条件を満たしたなら、成熟度を `L3 整った` に上げ、
   `Skill('architecture-design')` で `docs/design.md` を更新する
4. コミットする（接頭辞 `docs:`）

## 完了時の報告

1. 返した負債（`D##` とコミットハッシュ）
2. 見送った負債と理由
3. テスト件数（開始 → 終了。同数であること）
4. 新たに見つけた負債
5. 次の一手（通常は `/iterate` に戻る）

## やってはいけないこと

- 赤いテストのまま着手する
- 機能追加・バグ修正・仕様変更を混ぜる
- テストの期待値を実装に合わせて緩める・テストを削る
- 症状が出ていない箇所に先回りで抽象化を入れる
- 負債表に無い箇所を勝手に整理する
- 「ついでに全部きれいにする」（1 回の範囲は上位数件まで）
