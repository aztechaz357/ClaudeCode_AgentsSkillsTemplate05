# 骨組みを作り切る（完走の第一歩）

**引数（任意）:** 骨組みにする経路の説明（省略時は `docs/concept.md` の
典型シナリオから最も短い 1 本を選ぶ）。

**このコマンドの目的は「動くものを 1 つ手に入れる」こと。**
機能の正しさ・仕様の網羅は目的ではない（後の反復で足す）。
ただし **8 点セットと 4 層の骨格は、ここで一度立てる** ——
後から入れるほうが高くつくため。

手順の正は `Skill('walking-skeleton')` 。このコマンドはその実行手順と
サブエージェントの使い方を定める。

## 実行方針

**関与モードにかかわらず、骨組みは無停止で作り切る。**
骨組みは「判断」ではなく「通す」作業であり、ここで選択肢を出しても
学べるものが無い（選ぶべき設計がまだ存在しない）。
一緒に設計するのは骨組みが通った後の `/iterate` から。

停止するのは次の 3 つだけ:

1. **不可逆な操作** が骨組みに含まれる（削除・課金・外部送信）
2. **環境が整わない** （依存・権限・実行環境が無く、整備の判断が必要）
3. **骨組みが決まらない** （`docs/concept.md` の典型シナリオが具体的でない。
   AskUserQuestion で「どのコマンドで何が出れば通ったと言えるか」を聞く）

`.steering/local-mode.md` が存在する場合は無停止で実行せず、
`.claude/local-llm/policy.md` に従いステップごとに停止して報告する。

## 前提

- `CLAUDE.md` のプロジェクトプロファイルに `{` が残っていないこと
  （残っていれば先に `/setup-project`）
- `docs/backlog.md` が存在すること（無ければ先に `/backlog init`）

## ステップ0: 骨組みの宣言

1. `docs/concept.md` の「典型シナリオ」から最も短い 1 本を選ぶ
2. 次の 1 文が書けることを確認する。書けないならステップを進めず確認する:

```
`<コマンド>` を実行すると、<入力> から <観測できる出力> が出る
```

3. `docs/backlog.md` の「完走の定義」にこの 1 文を書き、S01 として最上段へ置く
4. `Skill('steering')` で `.steering/[YYYYMMDD]-S01-<名前>/` を作る
   （`tasklist.md` と `INDEX.md`）

## ステップ1: 要求仕様書と設計書（段1・段2）

骨組みでも **要求と設計を先に書く** 。ただし極端に薄く。

1. `docs/usdm/src/S01-<name>.html`: 要求 1・理由 1 行・仕様 1 条
   （`Skill('usdm')`）
2. `docs/design/S01-<name>.md`: 構造を表す図を 1 枚 ＋ 構成 10 行 ＋
   判断の記録（`Skill('functional-design')`）
   - **ここで 4 層の骨格を決める**（presentation / application / domain /
     infrastructure）。1 層 1 ファイルでよい
   - **外部 I/O があるなら契約（Port）を 1 本だけ切る** 。
     以降の全反復がこの形に載る（`Skill('layered-architecture')`）
   - 無ければ切らない。切らない判断も「判断の記録」に書く
3. 検証: `build_usdm.py` と `check_diagrams.ps1` がどちらも 0

## ステップ2: E2E テストを先に書く（Red 確認）

**この順序は動かせない。** テストが骨組みの定義そのものになる。

1. プロファイルの「統合テスト」パスに E2E テストを 1 本書く
   - 検証するのは **入口を叩いて出口を見る** ことだけ
   - 内部構造・クラス名を検証しない（構造は L1 では変わりうる）
   - docstring は 4 項目（テスト対象・入力・期待値・理由）
2. プロファイルのテストコマンドで実行し、 **失敗すること** を確認する
3. Red の出力（件数・失敗メッセージ）を記録する

芯のロジックの単体テストも 1 本書く（`unit-tester` に委譲可。
プロンプトに **「成熟度 L1。Red 確認まで。実装は書かない」** と明記する）。

## ステップ3: 通す最小の実装（段4）

`Skill('layered-architecture')` の「成熟度に応じた守り方」に従い、
**L1 の許容範囲で最短に書く** 。

許されること（すべて負債に記録すれば正式に許可される）:

- 固定値を返す・エラー処理をしない（落ちてよい）・設定をハードコードする

**やること**: 4 層に分ける（1 層 1 ファイルでよい）。
外部 I/O があるなら契約 1 本を通して呼ぶ。

**禁止**: 契約を 2 本以上切る・DI コンテナ・プラグイン機構・設定機構。
骨組みが通る前の抽象化は、通った後に必ず作り直しになる。

`coder` に委譲する場合は、プロンプトに
**「成熟度 L1。仮実装可。テストは変更しない。残した手抜きを列挙すること」**
を明記する。

## ステップ4: 全緑と実物の確認（段5）

1. プロファイルの全体テストコマンドを実行し、passed / skipped を記録する
2. **テストの緑だけでは完走ではない。** プロファイルの「動作確認」コマンドで
   実物を動かし、出力を得る
3. 得た出力を **そのまま** 記録に貼る（絶対ルール 7）
4. 動かない場合は E2E テストが入口を正しく叩いていない。テストを直す

## ステップ5: テスト結果まとめとマニュアル（段6・段7）

**ここを省かない。** 骨組みで作った 2 枚が、以降の全反復の型になる。

1. `docs/test-reports/S01-<name>.md`（`Skill('test-reporting')`）:
   実測の件数・仕様とテストの対応・実物の出力
2. `docs/manual.md` を新規作成する。 **共通 3 節を必ず作る** ——
   `## 1. 環境構築` / `## 2. 実行方法` / `## 3. テストの実行方法`
   （コマンドはプロファイルから写し、実際に動くことを確かめる）。
   その下に `## S01 <スライス名>` を足す

## ステップ6: 手抜きの記録と一式の確認（段8）

1. `docs/slices/S01-<name>.md`（ハブ）を作り、8 点セットへのリンク・実績・
   「残した手抜き」表を埋める（`Skill('slice-definition')`）
2. 各行を `docs/backlog.md` の負債表へ転記する（`D##` を採番）
3. 構成と現在地を生成する:

   ```
   <ツール実行コマンド> .claude/tools/build_structure.py
   <ツール実行コマンド> .claude/tools/check_deliverables.py
   <ツール実行コマンド> .claude/tools/build_status.py
   ```

4. `docs/backlog.md` を更新する:
   - 「骨組み」→ `通った（S01・YYYY-MM-DD）`
   - S01 の成熟度 → `L1 動く` ／「いま着手中」→ `なし`
5. コミットする（接頭辞 `骨組み:`）。本文に Red → Green の件数と
   実物の出力の要約を書く

## 完了条件

- [ ] E2E テストが 1 本あり、緑（Red → Green の証跡がある）
- [ ] 4 層に分かれている（外部 I/O があれば契約 1 本を経由している）
- [ ] プロファイルの動作確認コマンドで実物が動き、出力を貼った
- [ ] **`check_deliverables.py` が 0**（S01 の 8 点セットがそろっている）
- [ ] **`build_usdm.py` が 0**（理由・番号・トレースが通っている）
- [ ] `docs/manual.md` に共通 3 節がある（コマンドが実際に動く）
- [ ] `docs/backlog.md` の「骨組み」が `通った` になっている
- [ ] 残した手抜きが負債表に記録されている
- [ ] コミット済み（未コミットの変更が残っていない）

## 完了後の報告

次の 4 点だけを報告し、 **次の一手として `/iterate` を提示する** 。

1. 通った経路（実行したコマンドと実際の出力）
2. テスト件数（Red → Green）
3. 残した手抜きの件数と、痛み 高 のもの
4. 次に着手するスライス（バックログの最上段）

大枠を 1 画面で見たいときは `/status` を案内する。
