# 骨組みを作り切る（完走の第一歩）

**引数（任意）:** 骨組みにする経路の説明（省略時は `docs/concept.md` の
典型シナリオから最も短い 1 本を選ぶ）。

**このコマンドの目的は「動くものを 1 つ手に入れる」こと。**
機能の正しさ・層の分離・文書の網羅は目的ではない（すべて後の反復で足す）。

手順の正は `Skill('walking-skeleton')` 。このコマンドはその実行手順と
サブエージェントの使い方を定める。

## 実行方針

**原則としてユーザーの介入なしに完了まで進む。** 停止するのは次の 3 つだけ:

1. **不可逆な操作** が骨組みに含まれる（削除・課金・外部送信）
2. **環境が整わない** （依存・権限・実行環境が無く、整備の判断が必要）
3. **骨組みが決まらない** （`docs/concept.md` の典型シナリオが具体的でない。
   AskUserQuestion で「どのコマンドで何が出れば通ったと言えるか」を聞く）

`.steering/local-mode.md` が存在する場合は無停止で実行せず、
`.claude/local-llm/policy.md` に従いステップごとに停止して報告する。

## 前提

- `CLAUDE.md` のプロジェクトプロファイルに `{` が残っていないこと
  （残っていれば先に `/setup-project`）
- `docs/backlog.md` が存在すること（無ければ先に `/backlog init`）

## ステップ0: 骨組みの宣言

1. `docs/concept.md` の「典型シナリオ」から最も短い 1 本を選ぶ
2. 次の 1 文が書けることを確認する。書けないならステップを進めず確認する:

```
`<コマンド>` を実行すると、<入力> から <観測できる出力> が出る
```

3. `docs/backlog.md` の「完走の定義」にこの 1 文を書き、S01 として最上段へ置く

## ステップ1: E2E テストを先に書く（Red 確認）

**この順序は動かせない。** テストが骨組みの定義そのものになる。

1. プロファイルの「統合テスト」パスに E2E テストを 1 本書く
   - 検証するのは **入口を叩いて出口を見る** ことだけ
   - 内部構造・クラス名を検証しない（構造は L1 では未確定）
   - docstring は 4 項目（テスト対象・入力・期待値・理由）
2. プロファイルのテストコマンドで実行し、 **失敗すること** を確認する
3. Red の出力（件数・失敗メッセージ）を記録する

## ステップ2: 通す最小の実装

`Skill('layered-architecture')` の「成熟度に応じた守り方」に従い、
**L1 の許容範囲で最短に書く** 。

許されること（すべて負債に記録すれば正式に許可される）:

- 固定値を返す・1 ファイルに全部書く・層を分けない
- エラー処理をしない（落ちてよい）・設定をハードコードする

**禁止**: 層を切る・契約（インタフェース）を定義する・設定機構を作る・
プラグイン機構を作る。骨組みが通る前の抽象化は、通った後に必ず作り直しになる。

タスクを `tdd-implementer` に委譲する場合は、プロンプトに
**「成熟度 L1。仮実装可。残した手抜きをレポートに列挙すること」** を明記する。

## ステップ3: 全緑の確認

プロファイルの全体テストコマンドを実行し、passed / skipped の数値を記録する。

## ステップ4: 実物を動かす（完走の証拠）

**テストの緑だけでは完走ではない。** プロファイルの「動作確認」コマンドで
実物を動かし、出力を得る。

- 得た出力を **そのまま** スライス文書の「実績」に貼る（絶対ルール 7）
- 動かない場合は E2E テストが入口を正しく叩いていない。テストを直す

## ステップ5: 手抜きの記録

ステップ2 で残した手抜きをすべて書き出す。 **記録が漏れた手抜きは規約違反。**

1. `docs/usdm/src/S01-<name>.html` と `docs/slices/S01-<name>.md` を
   `Skill('slice-definition')` のテンプレートで作成し、
   「残した手抜き」表を埋める
2. 各行を `docs/backlog.md` の負債表へ転記する（`D##` を採番。
   痛み・返す条件を書く）

## ステップ6: 記録とコミット

1. `docs/backlog.md` を更新する:
   - 「骨組み」→ `通った（S01・YYYY-MM-DD）`
   - S01 の成熟度 → `L1 動く`
   - 「次の一手」→ 次に着手する S##
2. コミットする（接頭辞 `骨組み:`）。本文に Red → Green の件数と
   実物の出力の要約を書く

## 完了条件

- [ ] E2E テストが 1 本あり、緑（Red → Green の証跡がある）
- [ ] プロファイルの動作確認コマンドで実物が動き、出力を貼った
- [ ] `docs/backlog.md` の「骨組み」が `通った` になっている
- [ ] 残した手抜きが負債表に記録されている
- [ ] コミット済み（未コミットの変更が残っていない）

## 完了後の報告

次の 4 点だけを報告し、 **次の一手として `/iterate` を提示する** 。

1. 通った経路（実行したコマンドと実際の出力）
2. テスト件数（Red → Green）
3. 残した手抜きの件数と、痛み 高 のもの
4. 次に着手するスライス（バックログの最上段）
