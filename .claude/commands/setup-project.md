# プロジェクト初期化

`.claude/` のエージェント・スキル・ツールは **プロジェクト非依存のテンプレート**
です。プロジェクト固有の値（言語・コマンド・パス・層構成・規約）は
`CLAUDE.md` の **プロジェクトプロファイル** に集約され、全エージェントは
そこを正として動きます。

このコマンドは、そのプロファイルを対話で確定させ、開発を開始できる状態に
します。 **プロファイルが未整備のまま開発を始めない** —— エージェントが
コマンドやパスを推測し始め、決定論性が壊れます。

## ステップ1: 現状の知覚

1. リポジトリのルートを Glob / Read で調べる:
   - 依存定義ファイル（`pyproject.toml` / `package.json` / `go.mod` /
     `Cargo.toml` / `pom.xml` 等）→ 言語とパッケージマネージャの判定
   - 既存のソース・テストのディレクトリ構成
   - 既存の `CLAUDE.md`・`docs/` の有無
   - `.git` の既定ブランチ（`git symbolic-ref refs/remotes/origin/HEAD` または
     `git branch --list`）
2. 判定できたことと、できなかったことを整理する

## ステップ2: 未確定事項の確認

判定できなかった項目は **AskUserQuestion でまとめて確認する**
（推測で埋めない）。典型的な確認事項:

- プロジェクトの目的と対象ユーザー（1〜2文）
- テスト・ビルド・lint / typecheck のコマンド（未導入なら「未導入」）
- 統合テストの配置と実行コマンド
- 依存追加の方針（標準ライブラリ主義か・外部ライブラリ可か）
- 文書の言語（日本語 / 英語）とコミットメッセージの言語
- 凍結文書（触ってはいけない文書）の有無

## ステップ3: CLAUDE.md のプレースホルダーを埋める

**雛形は `CLAUDE.md` 本体にある** 。テンプレート版の `CLAUDE.md` には
プロファイルの全項目が `{}` のプレースホルダーで並んでいるので、それを
ステップ1〜2 で確定した値に置き換える（雛形をここに再掲しない ——
手順の正を二重化しないため）。

作業の要点:

1. `CLAUDE.md` を Read し、`{}` が残っている箇所を洗い出す
2. Edit で 1 項目ずつ実物の値に置き換える
3. **見出しと項目名は変更しない** —— 全エージェントがこの名前で参照する
4. 判定できなかった項目は空欄にせず「未整備」「なし」と明記する
   （空欄はエージェントが推測を始める原因になる）
5. 既存の `CLAUDE.md` がある場合は統合する。既存の記述を消さない
6. プロジェクト固有の規約（プロファイルに枠が無いもの）は
   「開発ルール」節に追記する

置き換え漏れの確認: `CLAUDE.md` に `{` が残っていないことを Grep で確認する。

## ステップ4: 骨組みの作成

プロファイルで決めた構成に沿って、不足しているものを作る:

1. `docs/requirements/` `docs/design/proposals/` のディレクトリと
   ロードマップ表（空でよい）
2. **全体構想**（`docs/concept.md`）—— `Skill('concept-definition')` で
   作る。狙い・非目標・割り切り・脅威モデル・フェーズ計画をここで確定させ、
   フェーズ候補をロードマップ表に反映する。プロファイルの「安全機構」節は
   ここの脅威モデルを根拠に埋める（順序: 全体構想 → 安全機構）
3. 層ディレクトリとテストのミラー構成（新規プロジェクトの場合）
4. **アーキテクチャテスト**（依存ルールの機械検証）—— 未整備なら
   このタイミングで作る。決定論性の土台であり、後回しにしない
5. `.gitignore` に `.steering/` と `.claude/settings.local.json` を追加
6. `.claude/skills/repository-structure/template.md` のスナップショットを
   実物に合わせて更新（テンプレート版は `{}` の雛形のまま）
7. `.claude/core_files.txt` に「core 無変更」の検査対象を記入する
   （中核がまだ無い初期フェーズでは、決まった時点で記入すると
   決定して残す。空のままだと `check_unchanged.py` は
   終了コード 2 で失敗する）
8. `.claude/settings.json` に、このプロジェクトで頻出する読み取り専用
   コマンドの許可を必要なだけ追加する（個人環境の許可は
   `.claude/settings.local.json`。こちらは共有しない）
9. **実行環境** —— 開発コンテナを使うなら `.devcontainer/allowed-domains.txt`
   を、このプロジェクトが本当に必要とする宛先だけに削る（既定は Claude Code +
   主要パッケージレジストリ）。使わないなら `.devcontainer/` を削除して、
   その旨をプロファイルに書く
10. **フックの設定** —— `.claude/hooks/protected_paths.txt` に凍結文書と
   生成物のパスを記入する（プロファイルの「凍結文書」と揃える）。
   `denied_commands.txt` を読み、このプロジェクトで止めたい破壊的操作を
   足す。整形コマンドが決まっているなら `post-edit-lint.ps1` を
   `settings.json` に配線する（手順は `.claude/hooks/README.md`）

## ステップ5: 確認と報告

1. プロファイルの各コマンドを実際に実行して通ることを確認する
   （テストコマンドが動かないプロファイルは無価値）
2. 初期化内容をコミットする
3. ユーザーに報告する: 確定したプロファイル・作った骨組み・
   未確定のまま残った項目（あれば）

## 注意

- **プロファイルの項目名を変えない** 。エージェントが名前で参照している
- 判定できない項目を推測で埋めない。確認するか「未整備」と明記する
- 既存プロジェクトへの適用では、既存の構成を尊重してプロファイルを
  **実物に合わせる**（テンプレートに合わせて既存構造を作り変えない）
