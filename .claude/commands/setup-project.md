# プロジェクト初期化

`.claude/` のエージェント・スキル・ツールは **プロジェクト非依存のテンプレート**
です。プロジェクト固有の値（言語・コマンド・パス・層構成・規約）は
`CLAUDE.md` の **プロジェクトプロファイル** に集約され、全エージェントは
そこを正として動きます。

このコマンドは、そのプロファイルを対話で確定させ、開発を開始できる状態に
します。 **プロファイルが未整備のまま開発を始めない** —— エージェントが
コマンドやパスを推測し始め、決定論性が壊れます。

プロセス自体（成熟度・反復の型・完了条件）の正は
`.claude/skills/agile-process/` 。このコマンドは **プロファイルを確定させ、
`/skeleton` を始められる状態にする** ところまでを担う。

## ステップ1: 現状の知覚

1. リポジトリのルートを Glob / Read で調べる:
   - 依存定義ファイル（`pyproject.toml` / `package.json` / `go.mod` /
     `Cargo.toml` / `pom.xml` 等）→ 言語とパッケージマネージャの判定
   - 既存のソース・テストのディレクトリ構成
   - 既存の `CLAUDE.md`・`docs/` の有無
   - `.git` の既定ブランチ（`git symbolic-ref refs/remotes/origin/HEAD` または
     `git branch --list`）
2. 判定できたことと、できなかったことを整理する

## ステップ2: 未確定事項の確認

判定できなかった項目は **AskUserQuestion でまとめて確認する**
（推測で埋めない）。典型的な確認事項:

- プロジェクトの目的と対象ユーザー（1〜2文）
- **完走の定義** —— どのコマンドで何が出れば「通った」と言えるか
  （`/skeleton` の入力になる。最も重要な確認事項）
- **他人に渡す予定があるか** —— 成熟度の上限が決まる
  （自分だけなら L2 で完成、渡すなら L3）
- テスト・ビルド・lint / typecheck のコマンド（未導入なら「未導入」）
- 統合テスト（E2E）の配置と実行コマンド
- **動作確認コマンド** —— 実物を動かして出力を得る手段
  （反復ごとに使う。テストの緑だけでは完走の証拠にならない）
- 依存追加の方針（標準ライブラリ主義か・外部ライブラリ可か）
- 文書の言語（日本語 / 英語）とコミットメッセージの言語
- 凍結文書（触ってはいけない文書）の有無

## ステップ3: CLAUDE.md のプレースホルダーを埋める

**雛形は `CLAUDE.md` 本体にある** 。テンプレート版の `CLAUDE.md` には
プロファイルの全項目が `{}` のプレースホルダーで並んでいるので、それを
ステップ1〜2 で確定した値に置き換える（雛形をここに再掲しない ——
手順の正を二重化しないため）。

作業の要点:

1. `CLAUDE.md` を Read し、`{}` が残っている箇所を洗い出す
2. Edit で 1 項目ずつ実物の値に置き換える
3. **見出しと項目名は変更しない** —— 全エージェントがこの名前で参照する
4. 判定できなかった項目は空欄にせず「未整備」「なし」と明記する
   （空欄はエージェントが推測を始める原因になる）
5. 既存の `CLAUDE.md` がある場合は統合する。既存の記述を消さない
6. プロジェクト固有の規約（プロファイルに枠が無いもの）は
   「開発ルール」節に追記する

置き換え漏れの確認: `CLAUDE.md` に `{` が残っていないことを Grep で確認する。

## ステップ4: 最小の土台の作成

**必要なものだけ作る。空のファイル・使わないディレクトリを先に作らない**
（`docs/design.md`・`docs/reference.md`・`docs/manual.md`・`docs/glossary.md`
は必要になった時点で作る）。

1. **ゴールと完走の定義**（`docs/concept.md`）—— `Skill('concept-definition')`
   で作る。埋めるのは **一行要約と「完走の定義」の 2 つだけでよい**
   （非目標・割り切りは必要になった反復で埋める）。プロファイルの
   「安全機構」節はここの脅威モデルを根拠に埋める
2. **バックログ**（`docs/backlog.md`）—— `agile-process` スキルの
   `backlog-template.md` を写し、典型シナリオを縦切りスライス 3〜8 本に割る。
   S01 は最も薄い経路（骨組み）にする
3. `docs/slices/` のディレクトリ（空でよい。反復ごとに 1 枚ずつ増える）
4. 層ディレクトリとテストのミラー構成 —— **作らなくてよい** 。
   骨組みが通ってから L2 の反復で分ける（`layered-architecture` の
   「成熟度に応じた守り方」）。既存プロジェクトなら実物の構成を尊重する
5. **アーキテクチャテスト**（逆流の機械検証）—— 骨組みが通ってから作る。
   L1 では逆流が許されるので、この段階では意味がない。
   プロファイルの該当行には「未導入（L2 で導入）」と書く
6. `.gitignore` に `.steering/` と `.claude/settings.local.json` を追加
7. `.claude/skills/repository-structure/template.md` のスナップショットを
   実物に合わせて更新（テンプレート版は `{}` の雛形のまま）
8. `.claude/core_files.txt` は **空のままでよい** 。L3 に到達し今後
   書き換えないと決めたファイルができた時点で記入する
   （空のままだと `check_unchanged.py` は終了コード 2 で失敗するが、
   L3 まで使わないので問題ない）
9. `.claude/settings.json` に、このプロジェクトで頻出する読み取り専用
   コマンドの許可を必要なだけ追加する（個人環境の許可は
   `.claude/settings.local.json`。こちらは共有しない）
10. **実行環境** —— 開発コンテナを使うなら `.devcontainer/allowed-domains.txt`
   を、このプロジェクトが本当に必要とする宛先だけに削る（既定は Claude Code +
   主要パッケージレジストリ）。使わないなら `.devcontainer/` を削除して、
   その旨をプロファイルに書く
11. **フックの設定** —— `.claude/hooks/protected_paths.txt` に凍結文書と
   生成物のパスを記入する（プロファイルの「凍結文書」と揃える）。
   `denied_commands.txt` を読み、このプロジェクトで止めたい破壊的操作を
   足す。整形コマンドが決まっているなら `post-edit-lint.ps1` を
   `settings.json` に配線する（手順は `.claude/hooks/README.md`）

## ステップ5: 確認と報告

1. プロファイルの各コマンドを実際に実行して通ることを確認する
   （テストコマンドと **動作確認コマンド** が動かないプロファイルは無価値）
2. 初期化内容をコミットする
3. ユーザーに報告する: 確定したプロファイル・作った土台・
   未確定のまま残った項目（あれば）
4. **次の一手として `/skeleton` を提示する** —— 骨組みが通るまでは
   他のことをしない（`agile-process` の PM ルール）

## 注意

- **プロファイルの項目名を変えない** 。エージェントが名前で参照している
- 判定できない項目を推測で埋めない。確認するか「未整備」と明記する
- 既存プロジェクトへの適用では、既存の構成を尊重してプロファイルを
  **実物に合わせる**（テンプレートに合わせて既存構造を作り変えない）
