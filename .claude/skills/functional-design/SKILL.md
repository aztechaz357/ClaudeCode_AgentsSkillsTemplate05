# 実装前設計（設計書）作成スキル

開発プロセスの第 2 工程です（要求仕様書 → **設計書** → TDD 実装 → 統合テスト）。
フェーズ単位の実装前設計書 `docs/design/proposals/P##-<name>.md` を、
所定の構成・品質で作成します。

設計書の役割は **実装フェーズで LLM に考えさせる量を減らすこと** です。
レイヤー配置・シグネチャ・テスト観点まで確定していれば、実装は
「設計書をコードに翻訳する」決定論的な作業に近づきます。

## 前提条件

設計書の作成を開始する前に、以下を読むこと:

1. `CLAUDE.md`（プロジェクトプロファイル含む）- 開発規約・層構成・家風パターン
2. **該当フェーズの要求仕様書**（`docs/requirements/P##-<name>.md`）- 設計の入力
3. 全体概要（architecture 相当）- 全体像と設計上の決定事項
4. 変更対象レイヤーの現状設計書
5. ロードマップ表 - P## 番号の採番元

## 出力先と採番

```
docs/design/proposals/P##-<name>.md   （1フェーズ1ファイル）
```

- P## は対応する要求仕様書と同じ番号を使う
- 作成と同時にロードマップ表の該当行を「🔧 設計済み・未実装」に更新する
- 実装完了時は該当の現状設計書へ反映し、設計書冒頭を
  「✅ 実装済み・反映済み」に更新する（doc-syncer の領分）

## テンプレートとガイド

- テンプレート: ./template.md
- 詳細ガイド（各セクションの書き方・良い例）: ./guide.md

## 品質チェック（作成後）

- [ ] 構成が揃っているか（目的 / 位置づけ / 契約・クラス / 既存変更点 /
      テスト観点 / 決定と却下案 / 既知の制限）
- [ ] **要求仕様書の受け入れ条件がすべて設計でカバーされているか**
      （条件 → 設計要素の対応が追えるか）
- [ ] レイヤー配置が依存ルールに適合しているか（core 無変更が原則）
- [ ] テスト観点がテストコードに翻訳できる具体性か
- [ ] 図を構文検証したか（`.claude/tools/` の図検証ツール）
- [ ] `**強調**` の前後に半角スペースがあるか
- [ ] ロードマップ表のステータスを更新したか
