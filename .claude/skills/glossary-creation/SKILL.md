# 用語集作成スキル

プロジェクトの用語集 `docs/glossary.md` を作成・更新するスキルです。

用語集の目的は **エージェント間・工程間で言葉の意味を揃えること** です。
要求仕様書・設計書・コードで同じ概念が別の名前で呼ばれると、
トレーサビリティが壊れ、LLM に余計な推論をさせることになります。

## 用語集の役割分担

- **glossary.md**: 概念・パターン・運用の言葉の定義（「フェイルソフトとは何か」）
- **reference.md**: クラス・関数・定数の一覧（「その型のフィールドは何か」）

クラスの説明を glossary に書かない。概念の説明を reference に書かない。

## 用語の収集元

1. `CLAUDE.md`（プロジェクトプロファイル含む）- 開発フロー・規約の用語
2. 要求仕様書（`docs/requirements/`）- ドメイン用語・ユーザーが使う言葉
3. 全体概要・現状設計書・設計書 - アーキテクチャ・設計パターンの用語
4. マニュアル - ユーザー向け機能の用語

## 定義すべき用語カテゴリ

| カテゴリ | 例 |
|---|---|
| ドメイン | プロジェクト固有の業務・対象領域の言葉（要求仕様書由来） |
| アーキテクチャ | クリーンアーキテクチャ（4層）、Composition Root、依存ルール、契約 |
| 設計パターン | core 無変更、共有状態注入、デコレータ（包み順）、図面先行 |
| 安全設計 | フェイルソフト、フェイルクローズ、許可リスト、信頼境界 |
| 運用 | フェーズ（P##）、要求仕様書、設計書、マイクロコミット、TDD（Red→Green）、統合テスト、凍結文書 |
| 外部要素 | 依存する外部サービス・ライブラリ・実行環境 |

## 作成・更新手順

1. 収集元の文書から用語を洗い出す
2. `./template.md` の形式で `docs/glossary.md` を作成・更新する
3. 定義は **本プロジェクトでの意味** を書く（一般論の辞書にしない）
4. 関連するクラスがあれば reference.md へのポインタを添える
5. 文書規約（`**強調**` 前後の半角スペース等）を守る

## 品質チェック

- [ ] 定義がプロジェクト固有の意味になっているか（一般論で終わっていないか）
- [ ] reference.md と役割が重複していないか
- [ ] 各文書で同じ用語が同じ意味で使われているか（表記ゆれの検出も本スキルの仕事）
- [ ] 要求仕様書のドメイン用語が拾えているか
