# リファクタリングスキル（refactoring）

反復開発では「きれいにする」を **独立した工程** として持つ。
実装中に整えようとして止まるのを防ぎ、代わりにここで確実に返す。

## 前提: 振る舞いを変えない

> **リファクタリング = 外から見た振る舞いを変えずに内部構造を変えること。**

- 開始時に全テストが緑であることを確認する。 **赤なら着手しない**
  （赤いままの整理は、直したのか壊したのか区別できない）
- 機能追加・バグ修正・仕様変更を **混ぜない** 。見つけたら
  バックログに積んで、リファクタリングを終えてから別コミットでやる
- テストの期待値を変えたくなったら、それはリファクタリングではない。止まって報告する

## 何を返すか（負債表が入力）

`docs/backlog.md` の負債表を読み、次の順に返す。

| 順 | 対象 | 理由 |
|---|---|---|
| 1 | 痛み **高** の負債 | 次の反復の速度を直接下げている |
| 2 | 「返す条件」が満たされた負債 | 先送りの根拠が消えた |
| 3 | 同じ手抜きが 2 か所以上に増えた負債 | 3 か所目が出る前に止める |
| 4 | 痛み 中 で、これから触る場所にあるもの | 触るついでが最も安い |

**痛み 低 で、返す条件が満たされておらず、これから触らない負債は返さない。**
返さない判断も記録に残す（負債表の状態を `見送り（YYYY-MM-DD・理由）` にする）。

## 1 手の粒度

1 手 = **1 種類の変換 × 1 コミット** 。複数種類を混ぜない。

| 変換 | 内容 |
|---|---|
| 名前を変える | 変数・関数・クラス・ファイル名。中身は触らない |
| 抽出する | 長い関数から関数を切り出す。呼び出し順は変えない |
| 移す | ファイル・関数を正しい層へ移動する。中身は触らない |
| 重複を統合する | 2 か所以上の同じ処理を 1 つにする |
| 契約を切る | domain に契約を置き、実装を infrastructure に移して注入する |
| 仮実装を本実装に置き換える | ハードコードを引数・設定へ（L1 → L2 の主作業） |

各手の後に **全テストを実行して緑を確認し、コミットする** 。
まとめてやって最後に実行すると、壊した箇所を特定できなくなる。

## 手順

1. **知覚**: `git status` が clean であることと、全テストが緑であることを
   プロファイルのテストコマンドで確認する。件数を記録する（開始時の基準値）
2. **選ぶ**: 負債表から 1 件（上記の順序）。返す範囲を宣言する
3. **安全網の確認**: その範囲を覆うテストがあるか確認する。
   **無ければ先にテストを足す**（テストを足すコミットと、整理するコミットは分ける）
4. **1 手ずつ**: 変換 → 全テスト緑 → コミット（接頭辞 `整理:`）を繰り返す
5. **検証**: 開始時と **同じテスト件数が緑** であることを確認する
   （件数が減っていたらテストを消している。増えていたら機能を混ぜている）
6. **記録**: 負債表の状態を `済（コミットハッシュ）` にする。
   スライス文書の「残した手抜き」にも `済` を付ける
7. **層の検証**: 層をまたぐ移動をしたら、アーキテクチャテスト
   （プロファイル参照）で逆流ゼロを確認する

## 成熟度 L3 へ上げる場合の追加作業

L3 は「他人が読んで変更できる」レベル。上記に加えて:

- [ ] 逆流ゼロ（アーキテクチャテストが緑）
- [ ] すべての関数・クラスに docstring（役割 / 引数 / 戻り値）
- [ ] 重複した処理が 1 か所に統合されている
- [ ] `docs/design.md`（現状設計 1 枚）に構造を反映
- [ ] 外から呼べるものが増えていれば `docs/manual.md` を更新
- [ ] 該当スライスの負債が 0 件（または `見送り` の理由が明記されている）

L3 に上げるのは **他人に渡す予定があるときだけ** 。
自分だけが使う道具は L2 で完成としてよい（`agile-process` の PM ルール）。

## やってはいけないこと

- 赤いテストのまま整理を始める
- 機能追加・バグ修正を混ぜる（コミットが読めなくなる）
- テストの期待値を実装に合わせて緩める
- 症状が出ていない箇所に先回りで抽象化を入れる（契約・プラグイン機構・設定機構）
- 「ついでに全部きれいにする」（1 回のリファクタリングで返すのは負債表の
  上位数件まで。全部返すまで止めないと反復が止まる）
- 負債表に無い箇所を勝手に整理する（記録に無い変更は追えない）

## 完了時の報告

- 返した負債の一覧（D## とコミットハッシュ）
- 見送った負債とその理由
- テスト件数（開始時 → 終了時。同数であること）
- 新たに発見した負債（負債表に追記済みであること）
