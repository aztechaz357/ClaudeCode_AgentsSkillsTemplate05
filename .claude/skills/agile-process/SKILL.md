# 反復開発プロセス（agile-process）

このプロジェクトの開発は **まず完走 → インクリメンタルに改善** で進む。
このスキルはその進め方の正であり、他のスキル・エージェントは
ここに書かれた成熟度と完了条件を基準に判定する。

## 中心原則

1. **動くものが最初の成果物** —— 端から端まで通る経路（骨組み）を最初に
   作り切る。層の分離・網羅的な仕様・完全な文書は後から足す
2. **完璧を積み上げない** —— 1 つのスライスを完璧にしてから次へ行くのではなく、
   **全スライスを L1（動く）まで上げてから** L2（固い）に上げる
3. **手抜きは許す。隠すのは許さない** —— 仮実装・ハードコード・欠けた
   失敗経路は、スライス文書の「残した手抜き」に書けば正式に許可される。
   書かずに残すことだけが禁止
4. **テストは省かない** —— 省くのは前工程の文書と構造であって、テストではない。
   L1 でも「E2E 1 本 + 芯のユニット」がテスト先行で必要
5. **きれいにするのはリファクタリング工程の仕事** —— 実装中に整えようとして
   止まらない。負債としてバックログに積み、緑を保ったまま後で返す

## 3 つの状態（環境に置く。会話に置かない）

| 状態 | 置き場所 | 役割 |
|---|---|---|
| ゴールと完走の定義 | `docs/concept.md` | 何ができたら完走かを 1 か所で決める（`concept-definition`） |
| バックログ | `docs/backlog.md` | 縦切りスライスと負債の優先順位・成熟度（PM の正） |
| スライス 1 枚 | `docs/slices/S##-<name>.md` | 仕様・薄い設計・残した手抜き（`slice-definition`） |

進捗は **バックログの成熟度列だけ** が正。他の文書に進捗を書かない。

## 縦切りスライス（S##）

スライスは **層ではなく経路で切る** 。「入力を受け取り、処理し、
観測できる結果を返す」までが 1 本に入っていること。

- **良い切り方**: 「CSV を渡すと件数が標準出力に出る」
  （入口・処理・出口が全部入っている = L1 で価値が観測できる）
- **悪い切り方**: 「domain 層のエンティティを定義する」
  （横切り。単体では動かないので完走に近づかない）

1 スライスの目安は **半日以内で L1 に到達する量** 。超えるなら分割する。

## 進め方の全体像

```
/setup-project  … プロファイルを確定（1 回）
/backlog        … ゴールとスライス一覧を作る・並べ替える
/skeleton       … 骨組みを作り切る（S01 を L1 に。1 回だけ）
  ↓
/iterate        … スライスを 1 本ずつ L1 に上げる（WIP = 1）★ここを繰り返す
  ↓ 全スライスが L1 になったら
/iterate        … 上位から L2 に上げる（境界値・失敗経路）
/refactor       … 負債を返す（L3 へ）
/add-feature    … 厚く書く必要がある 1 本だけ、通しの重い経路で
```

**骨組みができるまでは L2 以上に手を出さない。**
この 1 行がゴールまでの距離を決める。

## 成熟度レベルと段階別の完了条件

4 段階（L0 未着手 / L1 動く / L2 固い / L3 整った）。
**各レベルの完了条件の詳細表は `./maturity.md` を正とする** 。
実装検証・文書同期・レビューはすべて「今のレベルの条件」だけで判定し、
上のレベルの条件で不合格にしない。

要点だけ:

| レベル | 一言 | テスト | 許されること |
|---|---|---|---|
| L1 動く | 使える | E2E 1 本 + 芯のユニット | 仮実装・ハードコード・失敗経路の欠落（記録必須） |
| L2 固い | 壊れない | 仕様ごとに 1 本以上 | 構造の不揃い・文書の未整備 |
| L3 整った | 渡せる | 全緑 + 回帰 | なし（ここが完成） |

## いつ厚く書くか（薄いのが既定）

既定はスライス 1 枚（仕様 3 行 + 薄い設計 5 行）。
次のどれかに当てはまるスライスだけ、`/add-feature` の厚い経路を使う。

| 条件 | 厚く書く理由 |
|---|---|
| 不可逆な操作を含む（削除・課金・送信） | 後から直せない。設計を先に固める |
| 外部に公開する（他人が使う API・CLI） | 契約を変えられなくなる |
| 安全機構に触る（権限・入力検証・秘密情報） | 抜けが事故になる |
| データ形式を決める（保存形式・スキーマ） | 移行コストが後で発生する |
| 3 回作り直しても L1 にならない | 設計不足が原因。設計に戻る |

**どれにも当てはまらないなら薄いままで進む。** 判断に迷ったら薄い方。

## 反復 1 回の型（`/iterate` の中身）

1 回 = 半日以内。長くなったらスライスの切り方を疑う。

1. **選ぶ**: バックログの最上段（1 本だけ。WIP = 1）
2. **薄く決める**: スライス文書に仕様（正常系 1〜3 行）と
   薄い設計（層・ファイル・入口の関数名で 5 行）を書く
3. **TDD**: テスト先行 → Red 確認 → 最小実装 → 全緑
   （L1 では仮実装で緑にしてよい。`tdd-implementer`）
4. **通す**: E2E を実行し、端から端まで動くことを実際の出力で確認する
5. **記録**: 残した手抜きをスライス文書と `docs/backlog.md` に負債行として積む
6. **更新**: バックログの成熟度を上げ、コミットする
7. **判定**: 負債が反復 2 回分たまったら次は `/refactor` を挟む

## 禁止事項（重さが戻る動き）

- 骨組みができる前に層を分ける・契約を切る・文書を揃える
- スライスを L1 で止めずに、その場で L2・L3 まで仕上げる
  （他のスライスが L0 のままなら、それは完璧の積み上げ）
- テスト先行を飛ばす（Red 未確認の実装）
- 手抜きを記録せずに残す
- バックログを更新せずに次の反復へ進む（状態を会話に置かない）
