# 成熟度レベルと段階別の完了条件（DoD）

**このファイルは完了条件の正。** 実装検証・統合テスト・文書同期・
コードレビューは、対象スライスの **現在のレベルの条件だけ** で合否を判定する。
上のレベルの条件を持ち出して不合格にしてはならない（それが「完璧の積み上げ」
の入口になる）。

**どのレベルでも成果物の種類は 8 点で固定** （`./deliverables.md` が正）。
レベルで変わるのは各成果物の **深さだけ** 。「L1 だからマニュアルは書かない」
のような種類の省略は、どのレベルでも認められない。

## レベルの意味

| レベル | 表記 | 一言で言うと | 誰が満足するか |
|---|---|---|---|
| L0 | `L0 未着手` | バックログに 1 行あるだけ | 誰も |
| L1 | `L1 動く` | 端から端まで通り、実際に使える | 作った本人が使える |
| L2 | `L2 固い` | 境界値・失敗経路まで仕様どおり | 本人が安心して任せられる |
| L3 | `L3 整った` | 構造と文書が整い、他人が触れる | 他人が読んで変更できる |

## 段階別の完了条件

| 観点 | L1 動く | L2 固い | L3 整った |
|---|---|---|---|
| **成果物の種類** | **8 点すべて**（`./deliverables.md`） | 同左 | 同左 |
| **要求（USDM）** | 要求 1 個 ＋ **理由 1 行**（必須） | 要求は変えない。分割が必要なら下位要求を足す（理由も併記） | 変更なし |
| **仕様（USDM）** | 正常系 1〜3 条（`##-n` で親要求に紐づく） | 境界値・失敗経路・既定値を追加し全条件 `☑` | 変更なし（L2 の条件を維持） |
| **入出力の例** | **正常系 `N1` と異常系 `E1` を 1 例ずつ**（要求・設計の両方に。同じ ID が同じケースを指す） | 例は 2 行のまま。網羅はテスト仕様書側で増やす | 変更なし |
| **設計書** | `docs/design/S##-*.md` 10 行 ＋ 入出力の例 ＋ **判断の記録**（理由・他の選択肢・メリデメ） | ＋失敗時の扱い・契約の一覧・データ形式 | `docs/design.md`（全体像）へ統合しリンクにする |
| **図（設計書に 4 種）** | クラス図・フローチャート・シーケンス図・状態遷移図を各 1 枚（ノード数は最小限。 **枚数は減らさない** ） | 同左（分岐と失敗経路をノードとして足す） | 同左 ＋ `docs/architecture.md` の層の図 |
| **テスト仕様書** | `docs/test-specs/S##-*.md` 1 枚（採る観点 1〜2 個 ＋ 例 3〜6 行。`N1`・`E1` 必須） | 採った観点ごとに例を網羅（境界値・失敗経路） | ＋回帰の例。実行結果は書かない（それは結果まとめ） |
| **単体テスト** | 芯のロジックに 1〜3 本（テスト先行・Red 確認済み） | 仕様 1 条につき 1 本以上・境界値 | 回帰込みで全緑。契約のフェイクで外部 I/O に触らない |
| **統合テスト** | **E2E 1 本が緑** | 仕様 1 条につき 1 本以上 | 追加しない（既存が緑であることの確認のみ） |
| **テスト結果まとめ** | `docs/test-reports/S##-*.md` 1 枚（実行コマンド・実測件数・仕様対応表） | ＋失敗経路の結果・未カバー仕様 0 件 | ＋回帰結果・アーキテクチャテストの結果 |
| **マニュアル** | `docs/manual.md` の共通 3 節（環境構築・実行方法・テスト実行）＋ 当該スライスの節 | ＋落とし穴（症状 → 原因 → 対処） | ＋結果の読み方・既知の制限 |
| **実装** | 仮実装・ハードコード可（記録必須） | **仮実装ゼロ** 。ハードコードは設定・引数へ | 重複除去・命名の統一 |
| **層と契約** | 4 層に分ける。外部 I/O があるスライスは契約（Port）を 1 本切って注入する | 外部 I/O はすべて契約経由。配線は Composition Root 1 か所 | 逆流ゼロ・循環ゼロ。アーキテクチャテストが緑 |
| **エラー処理** | 落ちてよい（スタックトレースが出るだけでよい） | 想定内の失敗は結果値として返す | 同 + メッセージが利用者に読める |
| **ハブ（スライス文書）** | 8 点へのリンク ＋ 実績（実測の出力）＋ 残した手抜き | 同 ＋「残した手抜き」表が最新 | ＋ `docs/design.md`（全体像）へのリンク |
| **負債** | 記録されていること（内容は問わない） | 記録され、返す条件が書かれていること | 該当スライスの負債が 0 件 |
| **コミット** | 成果物ごと（1 コミット 1 意図） | 同 | 同 |

## 合否の出し方

判定は「現在のレベル → 次のレベル」の 1 段だけを見る。

```
対象: S03（現在 L1、目標 L2）
→ L2 の列だけを検査する
→ L3 の列（全体像への反映・重複除去）は検査しない
```

**成果物の有無は目視で数えない。** 判定の前に 2 本の機械検証を通す
（どちらも終了コード 0 が完了条件）。

```
<ツール実行コマンド> .claude/tools/check_deliverables.py --slice S##
<ツール実行コマンド> .claude/tools/build_usdm.py
```

レポートには次の 3 つだけ書く。

1. **達成**: 満たした条件
2. **未達**: 満たしていない条件（= 次にやること）
3. **越権指摘**: 上のレベルの条件に該当する所見は
   「L3 向け」と明示して負債候補として挙げる（不合格の理由にしない）

## レベルを飛ばしてよい / 飛ばせない場合

**L1 を飛ばして L2 から始めるスライス**（例外。厚い経路を使う）:

- 不可逆な操作を含む（削除・課金・外部送信）
- 安全機構に触る（権限・入力検証・秘密情報）
- データ形式・保存形式を決める

**L2 を飛ばして L3 に上げることは禁止** 。仮実装が残ったまま構造を整えると、
整えた構造ごと作り直しになる。

## プロジェクト全体の進め方（PM ルール）

| 状況 | 次にやること |
|---|---|
| 骨組み（S01）が L1 未満 | `/skeleton` 。他のことをしない |
| L0 のスライスが残っている | `/iterate` で L0 → L1 。**L2 に上げない** |
| 全スライスが L1 | `/iterate` で価値の高い順に L2 へ |
| 負債が反復 2 回分たまった | `/refactor` を 1 回挟む |
| 全スライスが L2 で、他人に渡す予定がある | `/refactor` と文書同期で L3 へ |
| 全スライスが L2 で、渡す予定がない | **L3 に上げない** 。次のゴールへ |

最後の行が重要 —— **L3 は誰かに渡すためのレベル** であり、
自分だけが使う道具を L3 に上げるのは過剰。ゴールの定義（`docs/concept.md`）が
「自分の作業を自動化する」なら L2 で完成としてよい。
