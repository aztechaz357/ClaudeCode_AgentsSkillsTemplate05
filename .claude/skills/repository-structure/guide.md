# 配置ガイド — 実例と例外ケース

SKILL.md の判定フローを、実例で補足するガイド。
**プロジェクトで実際に配置を決めたら、この表に実例を追記していく**
（このガイドを育てることが、次回の判断コストを下げる）。

## 配置の基本パターン

| 機能の種類 | domain（契約） | infrastructure（実装） | presentation | Composition Root |
|---|---|---|---|---|
| 外部サービス連携 | クライアント契約 | HTTP / SDK 実装 | — | 注入 |
| 永続化 | リポジトリ契約 | DB / ファイル実装 | — | 注入 |
| 承認・権限 | ポリシー契約 | 既定ポリシー | 対話 UI | 注入 |
| 観測（トレース・計測） | トレーサ契約 | 記録実装 | 表示コマンド | デコレータの包み順 |
| 共有状態（モード切替等） | 状態契約 | 状態ホルダ | 状態を操作する UI | 両者へ同一インスタンスを注入 |

パターン: **契約は domain・実装は infrastructure・表示や対話だけ presentation・
つなぐのは Composition Root** 。この分担が崩れる配置は設計から疑う。

## 新しい種類のコードが来たときの例外判断

- **新しいフロントエンド**（HTTP サーバ・GUI 等）: presentation に
  サブディレクトリを作る。application と domain のエンティティしか
  import しないこと
- **外部コマンド委譲**: 実装は infrastructure。コマンドの設定は設定ファイル
- **バッチ・スケジューラ**: 進行の組み立ては application（ユースケース）、
  起動トリガは presentation または Composition Root
- **どの層にも属さない気がするもの**: 設計に戻る。utils/ を作らない
