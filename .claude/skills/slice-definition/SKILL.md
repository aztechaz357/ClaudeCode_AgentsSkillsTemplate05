# スライス定義スキル（slice-definition）

反復開発の既定の文書は **スライス 1 枚** 。
要求仕様書と設計書を分けず、1 ファイルが成熟度に応じて育っていく。

```
docs/slices/S##-<name>.md   （1 スライス 1 ファイル）
```

厚く書く必要があるスライス（不可逆・外部公開・安全機構・データ形式）だけ、
`requirements-definition` → `functional-design` の重い経路を使う。
判定条件は `agile-process` スキルの「いつ厚く書くか」を正とする。

## 分量の上限（守ること）

L1 に着手する時点で書くのは、次の 2 つだけ。

| 節 | 上限 | 内容 |
|---|---|---|
| 受け入れ条件 | **3 行** | 正常系のみ。「入力 → 観測できる出力」 |
| 薄い設計 | **5 行** | 触るファイル・入口の関数名・データの流れ |

**上限を超えたら、書きすぎではなくスライスが大きすぎる。** 分割する。

L2 に上げるときに受け入れ条件へ境界値・失敗経路を追加し、
L3 に上げるときに `docs/design.md`（現状設計 1 枚）へ内容を移す。

## 受け入れ条件の書き方

L1 では **正常系を 1〜3 行** だけ。境界値と失敗経路は L2 の仕事なので、
ここで考え込まない（考え込むのが重さの正体）。

**L1 で書くもの**:

```markdown
- [ ] `tool count data.csv` を実行すると、データ行数が `N 行` の形で標準出力に出る
```

**L2 で足すもの**（このスライスを L2 に上げる反復で追記する）:

```markdown
- [ ] 空ファイルを渡すと `0 行` が出る（ヘッダのみも 0 行）
- [ ] 存在しないパスを渡すと終了コード 1 とパスを含むエラーが出る
- [ ] 列数が不揃いな行があっても処理を中断せず、警告を添えて件数を返す
```

チェックポイント（L1 用。3 つだけ）:

- [ ] 「入力 → 観測できる出力」の形か
- [ ] 実際に実行して確かめられるか（E2E テストに翻訳できるか）
- [ ] クラス名・ライブラリ名を書いていないか（それは薄い設計の領分）

## 薄い設計の書き方

図もクラス図もシーケンス図も **書かない** （L3 で必要になったら
`docs/design.md` に書く）。5 行で足りる。

```markdown
- 触るファイル: `src/tool/cli.py`（追加）、`src/tool/count.py`（新規）
- 入口: `cli.main(argv)` → `count.count_rows(path) -> int`
- 流れ: 引数 → ファイル読み → 行数 → 標準出力
- 層: presentation（cli）→ application（count）。逆流なし
- 仮実装: ヘッダ判定は「1 行目を常にヘッダとみなす」で済ませる
```

「仮実装」の行が書けているかが重要。 **ここに書いた仮実装が、
そのまま負債表の 1 行になる** 。

## 進め方

1. **知覚**: `docs/backlog.md` の対象行・`docs/concept.md` のゴール・
   隣接する既存スライス文書を読む。既に動いているコードがあれば実物を見る
2. **書く**: `./template.md` を写して受け入れ条件と薄い設計を埋める
3. **確認**: 曖昧なままでも **L1 なら進んでよい** 。ただし次の 2 つだけは
   AskUserQuestion で確認する（後戻りが大きいため）:
   - 出力の形式（他のものがこれを読む場合）
   - 不可逆な操作を含むかどうか
4. **反復後**: 「実績」に実際の出力を貼り、「残した手抜き」を埋め、
   バックログの負債表へ転記する

## 成熟度を上げるときの追記

| 上げる先 | 追記する節 | やること |
|---|---|---|
| L2 | 受け入れ条件 | 境界値・失敗経路・既定値を追加し、テストを 1 条 1 本以上に |
| L2 | 残した手抜き | 仮実装を消し、消した行に `済` を付ける |
| L3 | （移す） | 構造の内容を `docs/design.md` へ移し、ここはリンクにする |

## 品質チェック

- [ ] 受け入れ条件が 3 行以内（L1 の場合）
- [ ] 薄い設計が 5 行以内で、触るファイルと入口の関数名が書かれている
- [ ] 仮実装・ハードコードが「残した手抜き」に列挙されている
- [ ] 実績に **実際に実行した出力** が貼られている（推測禁止・絶対ルール 7）
- [ ] `docs/backlog.md` の成熟度と負債表が同期している
