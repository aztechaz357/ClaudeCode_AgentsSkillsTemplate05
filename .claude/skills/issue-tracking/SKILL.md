# チケット駆動スキル（issue-tracking）

チケットを **開発の窓** として使うための規約。
**このプロジェクトはチケット駆動が既定** で、違うのは置き場所だけ。

| モード | チケットの置き場所 | いつ選ぶか |
|---|---|---|
| `github` | GitHub Issue（1 Issue = バックログ 1 行） | **既定** 。リモートがあり `gh` が認証済み |
| `local` | ハブ `docs/slices/S##-*.md` の `## チケット` 節 | GitHub を使わない・リモートがまだ無い |
| `off` | 作らない | 工房レーンだけの短命なリポジトリ |

**モードは置き場所を変えるだけで、規約は変わらない。**
単位（1 チケット = バックログ 1 行）・正の所在（バックログ）・
反復のどこで触るか（段0 と段8 だけ）・閉じる条件（L3 到達）は共通。

## 大原則: 二重管理を作らない

| | 役割 | 正か |
|---|---|---|
| `docs/backlog.md` | 進捗・優先順位・負債・成熟度 | **正（唯一）** |
| チケット（Issue / ハブの節） | 外から見る窓・外から受ける口・ **履歴** | 写し（正ではない） |

**チケットは backlog の写しであって、進捗の正ではない。**
成熟度・着手中・次の一手をどこで確かめるかは、モードが `github` でも
`local` でも `off` でも `docs/backlog.md` のまま変わらない
（CLAUDE.md の絶対ルールを壊さない）。

同期の向きは 2 つだけ:

```
docs/backlog.md  ──(push)──▶  チケット     … S## / D## を写す
docs/backlog.md  ◀──(pull)──  GitHub Issue … 外から来た起票を取り込む（github のみ）
```

`pull` は **Issue をそのまま backlog へ書き込まない** 。
「今回のゴールに寄与するか」を `docs/concept.md` で判定してから、
スライス表・負債表・「今回のゴールの外」表のどれかへ入れる（`/backlog` と同じ判定）。

### 判断の記録

- **採用**: バックログを正とし、チケットは写し（片方向 push + 判定つき pull）。
  **そう考えた理由**: このテンプレートの絶対ルールは「進捗の正は
  `docs/backlog.md` だけ」であり、切り替えられる仕組みを正の側に置くと、
  モードを変えた瞬間に進捗の正が消える
- **他の選択肢 1**: Issue を正にし backlog を生成物にする。
  **メリット** = 外部協業が自然・GitHub の機能（マイルストーン・Projects）に乗れる。
  **デメリット** = モードを変えられない（`local` / `off` = 正が消える）・
  オフラインで進捗が読めない・既存の全エージェントとツール
  （`check_deliverables.py` ほか）が backlog を読む前提
- **他の選択肢 2**: 双方向同期。 **メリット** = どちらで編集してもよい。
  **デメリット** = 競合解決の規則が要り、決定論性が落ちる（設計思想 8 に反する）
- **却下の決め手**: 「途中でモードを切り替えられること」が要求なので、
  **どのモードでも何も失われない構造** が必須だった

### 判断の記録: ローカルチケットを新ファイルにしなかった（2026-08-14）

- **採用**: ハブ（`docs/slices/S##-*.md`）に `## チケット` 節を足す。
  **そう考えた理由**: ハブは既に「7 点への索引・実績・手抜き」を持つ
  スライス単位の 1 枚であり、GitHub Issue がそれに足しているのは
  **状態・目標・履歴の 3 つだけ** 。その 3 つを節として足せば足りる
- **他の選択肢 1**: `docs/tickets/S##.md` を新設。
  **メリット** = 「起票した」感が強い・GitHub へ移行するときの対応が明快。
  **デメリット** = ハブと同じ内容（7 点の状況）が 2 か所に並び、必ずずれる。
  このスキル自身の「二重管理を作らない」に反する
- **他の選択肢 2**: `docs/tickets.md` 1 枚に全部。
  **メリット** = 一覧性が最高。 **デメリット** = `docs/backlog.md` と
  見た目がほぼ同じになり、進捗の正がどちらか分からなくなる（最も避けたい失敗）
- **負債（`D##`）にローカルチケットを作らない理由**: 負債表の行が
  既に「出所・痛み・返す条件」を持つチケットそのもの。写しを作る意味が無い

## 設定（プロジェクトごと・途中で切り替え可）

正は **`CLAUDE.md` のプロジェクトプロファイルの「チケット追跡」節** 。

```markdown
### チケット追跡

- 使用: github
- リポジトリ: owner/repo
- ラベル: slice / debt / L1 / L2 / L3
```

- `使用:` の行だけが機械が読む値（`github` / `local` / `off`）。
  ここ以外に状態を置かない
- 旧設定の `on` は `github` の別名として読む（書くときは `github` に正規化する）
- 読み書きは推測せずツールで行う（下の「ツール」節）
- CLAUDE.md はコミットされるので、設定は **チーム全体で共有される** 。
  「自分の環境だけ別モード」は用意しない（環境ごとに挙動が変わるほうが事故が多い）

### 既定は `github`。使えないときは止まる

`github` なのに次のどちらかなら、 **推測で `local` に落とさず、そこで止めて
ユーザーに報告する** （絶対ルール 1・3）。

| 確認 | コマンド | 失敗したときに言うこと |
|---|---|---|
| 認証 | `gh auth status` | 「`gh auth login` を実行してください（認証情報は代行しません）」 |
| リモート | `gh repo view --json nameWithOwner` | 「リモートがありません。`/issue local` に切り替えますか」 |

自動フォールバックを入れない理由は、 **GitHub に出ているつもりで
ローカルにしか無い状態** に気づけないため（設定と現実の矛盾は
勝手に片方へ合わせない）。

### 切り替え手順

| やること | コマンド | 起きること |
|---|---|---|
| 現在の設定を見る | `/issue status` | 使用・リポジトリ・未同期の差分を報告 |
| GitHub を使う | `/issue github` | `使用: github` に書き換え、認証とリポジトリを確認し、差分を出す |
| ローカルに切り替える | `/issue local` | `使用: local` に書き換える。 **開いている Issue は消さない** |
| チケットをやめる | `/issue off` | `使用: off` に書き換える。 **開いている Issue は消さない** |

**途中で `github` にしたとき** —— それまでに進んだスライスも Issue にする。
既に L3 のスライスは `--include-done` を付けたときだけ作り、作った直後に閉じる
（履歴として残す意味がある場合のみ。既定では作らない）。

**`github` から離れるとき（`local` / `off`）** —— 開いている Issue には
「このリポジトリはチケットの置き場所を変えた。進捗は `docs/backlog.md` を見る」と
コメントを 1 件付けてから止める。 **黙って放置しない**（外から見た人が
生きている Issue だと誤解する）。閉じるかどうかはユーザーが決める（勝手に閉じない）。

**`local` から `github` へ移るとき** —— ハブの `## チケット` 節は
**消さない** 。履歴（誰がいつ何をしたか）はそこにしか無く、Issue には
移せないため。節の状態欄に「GitHub へ移行（#12）」と 1 行足して残す。

## 単位と対応付け

**チケット 1 本 = バックログの 1 行。** それ以外の粒度を作らない。

| バックログの行 | `github` | `local` |
|---|---|---|
| スライス `S03 CSV のフィルタ` | Issue `S03: CSV のフィルタ`（`slice` ＋ 成熟度） | `docs/slices/S03-*.md` の `## チケット` 節 |
| 負債 `D02 逆流している` | Issue `D02: 逆流している`（`debt`） | **作らない**（負債表の行そのものがチケット） |

対応付けの鍵はモードで違うが、 **どちらも対応表のファイルを持たない**
（持つと必ず実物とずれる）:

- `github` —— タイトルの接頭辞（`S##:` / `D##:`）
- `local` —— ハブのファイル名（`docs/slices/S##-*.md`）

共通の規則:

- 反復の 8 段ごとにチケットを切らない（8 倍に増えて窓の役を果たさない）。
  段の進行はチェックリストと履歴で表す
- 1 スライスの作業が大きすぎてチケットを割りたくなったら、それは
  **スライスの切り方の失敗** 。バックログ側でスライスを割る

## チケットの中身

**雛形の正は `sync_issues.py`** （手書きとツールの生成物がずれないよう、
雛形はツール側に 1 つだけ置く）。

### `github` —— Issue の本文（4 点）

1. スライス名と目標成熟度
2. 7 点セットのチェックリスト（要求・設計・単体テスト・実装・統合テスト・
   テスト結果まとめ・マニュアル）
3. `docs/backlog.md` と `docs/slices/S##-*.md` への相対リンク
4. **「進捗の正は `docs/backlog.md`。この Issue は写し」** の 1 行

### `local` —— ハブの `## チケット` 節

7 点セットのチェックリストは **ハブが既に持っているので繰り返さない** 。
この節が足すのは、GitHub Issue にあってハブに無かった 3 つだけ。

```markdown
## チケット

- 状態: 進行中
- 目標: L1 → L2
- 参照: `refs S03`（コミットメッセージの末尾に書く）

### 履歴（追記だけ。書き換えない）

- 2026-08-14 起票 —— L1 → L2
- 2026-08-15 完了 —— 状態 完了 / L3（到達済み）

> 進捗の正は `docs/backlog.md`。このチケットはその写し（窓）です。
```

| 欄 | 値 | GitHub での対応物 |
|---|---|---|
| 状態 | `未着手`（L0）/ `進行中` / `完了`（L3 到達） | open / closed |
| 目標 | `L1 → L2` | 成熟度ラベル |
| 履歴 | 日付つきの追記 | コメント |

**履歴を書き換えない。** 消すとチケットがただの現在値になり、
バックログの行と同じものに退化する（履歴だけがチケットの存在理由）。
節の位置はハブの H1 直後（`sync_issues.py` が入れる）。

## 反復のどこで何をするか（`github` / `local` 共通）

`/iterate` の段に **追加で** 乗る動作。段そのものは増やさない。

| 段 | チケット側の動作 | 誰が |
|---|---|---|
| 段0 選ぶ | 対象チケットが無ければ起票する。状態を `進行中` にし、`いま着手中` と同じ内容を履歴に足す | `issue-manager` |
| 段1〜7 | **触らない**（コミットメッセージ末尾に参照を書くだけ） | 各担当 |
| 段8 記録 | チェックリストを実測で更新し、目標成熟度を張り替え、完了報告を履歴に足す | `issue-manager` |
| L3 到達 | チケットを閉じる（`/issue close S##`。 **L1・L2 では閉じない** ） | `issue-manager` |

- 段1〜7 でチケットを触らないのは、 **7 点セットの担当が本業から逸れないため** 。
  更新は段0 と段8 に集約する
- 閉じるのは L3 のときだけ。L1・L2 は「動く・固い」であって完了ではない
- `local` で「閉じる」は状態を `完了` にすること（ファイルは消さない）

## `使用: off` のときの振る舞い

- 全エージェントは `gh issue` を **1 回も呼ばない** （読み取りも含む）
- ハブに `## チケット` 節を作らない
- コミットメッセージに `refs` を書かない
- `/issue` 以外のコマンドはチケットに言及しない（`/status` の表示も変わらない）
- `sync_issues.py` は終了コード 2 で拒否する（うっかり実行しても書き込まない）

**`off` は既定ではない。** 選ぶのは工房レーンだけの短命なリポジトリのように、
スライスもバックログも育てないと分かっているときだけ。

## コミット・PR との紐づけ

- コミットメッセージの **末尾** に参照を書く（接頭辞は既存のまま
  `実装:` `テスト:` などを使う）:

  | モード | 書き方 |
  |---|---|
  | `github` | `refs #12` |
  | `local` | `refs S03`（ハブのファイル名で辿れる） |

- **`fixes #12` / `closes #12` を書かない** —— GitHub が自動で閉じてしまい、
  「閉じるのは L3 のときだけ」という規約を機械が破る
- PR を作るかどうかはプロファイルの「push / PR」の値に従う（このスキルは変えない）

## ツール

前置コマンドはプロファイルの「`.claude/tools/` の Python ツール実行」。

| ツール | 用途 | 終了コード |
|---|---|---|
| `issue_mode.py` | `使用:` の行を読む / 書き換える | **0 = github、1 = off、2 = 判定不能、3 = local** |
| `sync_issues.py` | backlog とチケットの差分を出す（既定は dry-run） | 0 = 差分なし、1 = 差分あり / 適用失敗、2 = エラー・off |

**終了コードで分岐する。`0 以外 = 使わない` と読まない**
（`3` は local であって「使わない」ではない）。

```
<ツール実行コマンド> .claude/tools/issue_mode.py                    # 現在の設定
<ツール実行コマンド> .claude/tools/issue_mode.py --set github --repo owner/repo
<ツール実行コマンド> .claude/tools/issue_mode.py --set local
<ツール実行コマンド> .claude/tools/sync_issues.py                   # 差分（書き込まない）
<ツール実行コマンド> .claude/tools/sync_issues.py --apply           # 差分を反映
```

`--apply` は **書き込み** （`github` では外部へ、`local` ではハブへ）。
エージェントは実行前に必ずユーザーへ「何本起票する / 何本更新する /
何本閉じる」を提示して確認を取る（絶対ルール 4）。

### 実際の出力: `github`（このテンプレートで動かしたもの）

差分を見る（送信しない）:

```
差分: 作成 1 / 更新 0 / 閉じる 0 / 再オープン 0 / 取り込み候補 0
  作成      S01: Issue 駆動の動作確認  [slice, L0]
RESULT: 差分あり（未送信）。承認を得てから --apply する
```

承認を得てから反映する:

```
OK: create S01 https://github.com/aztechaz357/ClaudeCode_AgentsSkillsTemplate05/issues/1
RESULT: 反映した
```

同じコマンドをもう一度実行しても、二重に起票されない（冪等）:

```
差分: 作成 0 / 更新 0 / 閉じる 0 / 再オープン 0 / 取り込み候補 0
RESULT: 同期済み（送信するものは無い）
```

### 実際の出力: `local`（2026-08-14 に S01 で通したもの）

起票（`--apply` 前は 1 文字も書かない）:

```
差分: 起票 1 / 更新 0 / 完了 0 / 再開 0
  起票  S01  L1 → L2  [.../docs/slices/S01-csv.md]
RESULT: 差分あり（未反映）。承認を得てから --apply する
```

バックログで L3 に到達させてから、もう一度差分を見る:

```
差分: 起票 0 / 更新 0 / 完了 1 / 再開 0
  完了  S01  進行中 → 完了 / L3（到達済み）  [.../docs/slices/S01-csv.md]
```

反映後のハブ（ **起票の履歴が残ったまま完了が足される** ）:

```markdown
## チケット

- 状態: 完了
- 目標: L3（到達済み）
- 参照: `refs S01`（コミットメッセージの末尾に書く）

### 履歴（追記だけ。書き換えない）

- 2026-08-14 起票 —— L1 → L2
- 2026-08-14 完了 —— 状態 完了 / L3（到達済み）

> 進捗の正は `docs/backlog.md`。このチケットはその写し（窓）です。
```

## やってはいけないこと

- **チケットに進捗を書いて backlog を更新しない**（正が 2 つになる。最も重い違反）
- チケットを段ごとに切る・タスクごとに切る（窓ではなく作業ログになる）
- `使用: off` のまま `gh issue` を呼ぶ
- **`github` で `gh` が使えないときに、黙って `local` に落として進む**
  （設定と現実の矛盾は勝手に片方へ合わせない。止まって報告する）
- **終了コード 3（local）を「使わない」と読む**（`0 以外 = off` は誤り）
- **ローカルチケットの履歴を書き換える・消す**（履歴だけがチケットの存在理由）
- `local` で負債（`D##`）のチケットを作る（負債表の行そのものがチケット）
- 外から来た Issue を判定せずにバックログへ入れる（ゴールが溶ける）
- `fixes #` でコミットして GitHub に自動で閉じさせる
- L1・L2 でチケットを閉じる
- 対応表のファイルを別に作る（接頭辞とファイル名だけで足りる）
