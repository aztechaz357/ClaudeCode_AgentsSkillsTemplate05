# 選択肢を先に出す（option-first）

AI が決めて説明する形は速いが、 **人に判断の経験が積まれない** 。
かといって全段で承認を取ると WIP が詰まり、任せる意味が消える。

このスキルは **止まる場所を 3 つに限定** して、その 3 つでだけ選択肢を出す。
それ以外は推奨で進み、理由を記録する。

## 判断点の定義（この 3 つだけ）

| # | 判断点 | 例 |
|---|---|---|
| 1 | **後戻りコストが高い** | データ形式・永続化の構造・契約（Port）の切り方・並行性の方針 |
| 2 | **家風に影響する** | 以後の全スライスが従う型（エラーの返し方・ログの粒度・命名の型） |
| 3 | **名前が外に出る** | 公開 API・CLI の引数名・ファイル名・設定キー |

**これ以外は止まらない。** 層の割り当て・変数名・テストの本数・
仮実装で済ませるかは、`/iterate` の「停止しない」項目のまま。

プロジェクト固有の追加は `CLAUDE.md` の **「選択領域」** 節に書く
（そこに書かれたものだけが判断点として追加される。その場の判断で増やさない）。

## 選択肢の作り方（4 つの必須要素）

```markdown
**判断点**: {何を決めるのか。1 行}

1. **{案 A}（推奨）** —— {何をするか}
   - 選ぶと: {得られるもの}
   - 選ばないと: {失うもの・後で払う代償}
2. **{案 B}** —— …
3. **{案 C}** —— …

**推奨の理由**: {1 行}
**共通の前提**: {どれを選んでも変わらないこと}
```

1. **推奨を第 1 選択肢にする** —— 迷ったら 1 番を選べば進む。速度を殺さない
2. **「選ばないとどうなるか」を各案に書く** —— 学習効果はここからしか出ない。
   メリットの列挙は比較にならない
3. **3〜4 択に絞る** —— 5 つ以上は選べない。似た案は 1 つにまとめる
4. **却下案も残す** —— 後で「なぜその案にしなかったか」を辿れるようにする

**技術用語だけで書かない。** 選ぶのは人なので、
「何ができなくなるか」を具体で書く（「疎結合になる」ではなく
「あとで DB を差し替えるとき、触るファイルが 1 つで済む」）。

## 成熟度で関与の量を変える

| 目標 | 判断点で聞く回数 | 聞かないもの |
|---|---|---|
| L0 → L1 | **最大 1 回**（骨組みの形が決まる 1 点だけ） | 失敗時の振る舞い・拡張性 |
| L1 → L2 | 最大 2 回 | 名前の細部 |
| L2 → L3 | 聞かない（既に決まっているはず） | —— |

**L1 で 4 回聞くと反復が半日で終わらない。** 聞く回数の上限は
速度を守るための制約であって、丁寧さの指標ではない。

## ユーザーが選ばなかったとき

- **黙って止まらない。** 一定時間・一定の応答が無ければ **推奨で進む**
- 進めた事実と根拠を、選択肢ごと記録に残す
  （後から「そこは違う」と言われたときに、差し戻す地点が明確になる）
- 「聞いたのに決まらなかった」は失敗ではない。 **選択肢が提示された記録が
  残ること自体に価値がある**（次に同じ判断が来たとき参照できる）

## 決めた後の記録先（新しい成果物を作らない）

| 判断の広がり | 書く場所 |
|---|---|
| このスライスだけ | `docs/design/S##-*.md` の **「判断の記録」** |
| 2 つ以上のスライスが従う | `docs/decisions/ADR-###-*.md` |
| プロジェクト全体の型になった | `CLAUDE.md` の「家風パターン」 |

**7 点セットは 7 点のまま。** option-first は成果物を増やさず、
既にある「判断の記録」の中身を厚くするだけ
（選択肢と却下理由が入る）。

## いつ発火するか

| 工程 | 誰が | 何を聞くか |
|---|---|---|
| `/iterate` 段2（設計） | `designer` | 契約を切るか・データの持ち方（判断点 1・2 に当たるとき） |
| `/iterate` 段3（テスト） | `test-designer` | どのテスト観点を採るか（`test-design` スキル） |
| `/add-feature` | 親 | 厚い経路は判断点が多い。要求確定時と設計確定時の 2 回 |
| `/backlog init` | 親 | スライスの切り方（1 回だけ） |

## やってはいけないこと

- **判断点でないところで聞く**（層の割り当て・命名の細部・テストの本数）
- 選択肢を出さずに「どうしますか？」と聞く（丸投げは学習にならない）
- 推奨を書かない（選べない人が止まる）
- **選んでもらった後で別の案を実装する**（信頼が一度で壊れる）
- 承認が得られるまで待ち続ける（既定で進み、記録する）
- 判断点をその場で増やす（追加は `CLAUDE.md` の「選択領域」に書いてから）
