# ノートを残す（note-taking）

工房レーン（`workshop/notes/`）にノートを 1 本追加する手順。
レーンの定義・命名・索引は `workshop` スキルを正とする。

## ノートとそれ以外の切り分け

書く場所を間違えると、あとで探せなくなる。 表 1 で判定する。

表 1: 記録先の判定

| 記録したいこと | 書く場所 |
|---|---|
| 調べたこと・踏んだ罠・手順・思いつき | `workshop/notes/`（このスキル） |
| ゴール・完走の定義・非目標・割り切り | `docs/concept.md`（`concept-definition`） |
| スライスの受け入れ条件・薄い設計 | `docs/slices/`（`slice-definition`） |
| 進捗・優先順位・負債 | `docs/backlog.md`（`agile-process`） |
| 反復中の判断・ブロッカー・振り返り | `.steering/`（`steering`） |
| ツールの使い方 | そのツールの `README.md`（`quick-tool`） |
| 用語の定義 | `docs/glossary.md`（`glossary-creation`） |
| 恒久的な規約になったもの | `CLAUDE.md` またはスキル |

**反復中の判断は `.steering/` へ、残した手抜きは `docs/backlog.md` の
負債表へ** 。工房のノートは、スライスに紐づかない、いつでも読み返す
知識を置く場所。

## status の選び方

| status | 使うとき |
|---|---|
| `note` | 調べたこと・観測したこと（既定） |
| `howto` | 手順。次に同じことをするとき、そのまま辿れる形 |
| `idea` | まだ形になっていない思いつき。ツール化の候補 |
| `decision` | 決めたこと。 **なぜそう決めたか** を必ず書く |

## 手順

### 1. 既存のノートを確認する（30 秒）

`workshop/notes/INDEX.md` を読み、同じ話題のノートが無いか見る。

**あれば新しく作らず、そのノートに追記する。** 同じ話題が
複数ファイルに散るのが、ノートが使われなくなる一番の原因。
追記したら `updated` ではなく本文に日付見出しを足す
（ノートは時系列の積み重ねでよい）。

### 2. 雛形を作る

```
powershell -File .claude/tools/new_note.ps1 -Title <タイトル> -Slug <kebab-slug> -Tags "a,b"
```

- タイトルが日本語のときは `-Slug` を **必ず** 渡す
  （ASCII タイトルなら省略可能。自動導出される）
- `-Slug` は短く。`ps51-encoding` のように、後で思い出せる語にする
- 同じ日に同じ slug があれば終了コード 1 で拒否される（上書きしない）

### 3. 要点を先に書く（3 行以内）

**「要点」だけは必ず埋める。** 一覧から辿ったとき、人が読むのはここだけ。

- 悪い例: 「PowerShell の文字コードについて調べた」（何が分かったのか不明）
- 良い例: 「PS5.1 は BOM 無し UTF-8 の .ps1 を ANSI として読む。
  日本語コメントが次行を壊すので .ps1 は ASCII のみで書く」

要点が書けないなら、まだ書くには早い。調べ終えてから戻る。

### 4. 本文を埋める

- **コマンド・出力・コードは実際に動かしたものを貼る** （推測で書かない）
- 「背景 / きっかけ」は 1〜2 行でよいが省かない ——
  半年後の自分が「なぜこれを調べたのか」を思い出せなくなる
- 図を描くならアスキーアートは使わない（`writing-conventions`）
- `**強調**` の前後には半角スペースを置く

### 5. 関連を結ぶ

front matter の `related` に、関連するノートのファイル名・
ツール名を書く。本文からは `[表示名](2026-07-30-xxx.md)` でリンクする。

**リンクは多めに張ってよい。** まだ存在しないノートを指していても、
それは「次に書くべきノート」の印になる。

### 6. 索引を更新してコミットする

```
powershell -File .claude/tools/index_workshop.ps1
```

```
docs: ノート「<タイトル>」を追加

- workshop/notes/<日付>-<slug>.md を追加（status: <status>）
- 要点: <1行>
- notes/INDEX.md を再生成
```

## 完了チェックリスト

- [ ] 既存ノートへの追記で済まないことを確認した
- [ ] 「要点」が 3 行以内で、それだけ読めば内容が分かる
- [ ] コマンド・出力を実際に動かして貼った
- [ ] 「背景 / きっかけ」を書いた
- [ ] `tags` を付けた（既存のタグに寄せた）
- [ ] `related` を埋めた（無ければ空のままでよい）
- [ ] `index_workshop.ps1` を実行し、INDEX.md に載った
- [ ] コミットした

## ノートからツールへ

`status: idea` のノートが 2 回以上参照されたら、ツール化の合図。
`/tool` で `quick-tool` の手順に入り、できたツールの README から
元ノートへリンクを張る（ノート側の `related` にもツール名を足す）。

同じ手作業を 2 回以上繰り返していると気づいたときも同じ。
「ノートに手順を書く」で止めず、ツールにできないかを一度考える。
