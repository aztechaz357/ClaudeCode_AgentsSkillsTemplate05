# 追いつくスキル（catchup）

エージェントに任せると **生成の速度が読解の速度を超える** 。
このスキルは「全部読む」を諦め、 **決まったことだけを、後戻りコストの
高い順に読む** ための規約です。

## 前提: 追いつけない理由は 3 つある

| 型 | 症状 | このスキルが扱うか |
|---|---|---|
| **量** | 文書が積み上がり、読む時間が生成時間を超える | **扱う（本体）** |
| 乖離 | 頭の中の構造と実装がずれる | 扱わない（`layered-architecture` / 依存の検査） |
| 判断 | 決着済みで提示され、選ぶ経験が積まれない | 扱わない（判断点で止める規約は別） |

**`/catchup` は読む対象を絞る道具であって、承認の場ではない。**
止まるべき判断（不可逆・外部公開・安全機構）は、そもそも `/iterate` の
停止例外と `/add-feature` が受け持つ。

## 何を「決まったこと」とみなすか

コミットの本文ではなく、 **後から変えにくいものが増えたか** で見る。

| 影響度 | 何が起きたか | 出典 |
|---|---|---|
| **高** | ADR が増えた・設計書の「判断の記録」が変わった・要求（USDM）が変わった・プロファイル（`CLAUDE.md`）が変わった・`.claude/` の規約が変わった・依存が増えた | 後続の全スライスが従う |
| 中 | 実装が変わった・バックログの成熟度が動いた・負債が増減した | 局所的。読まなくても致命傷にならない |
| 低 | テストだけ・マニュアル・テスト結果まとめ・整理 | 結果の記録であって判断ではない |

**「高」を読み落とすことだけが事故** 。中・低は件数だけ分かればよい。
判定は `build_digest.py` が決定論的に行う（人が毎回考えない）。

## 読む順（ダイジェストが出したら、この順に読む）

1. **ADR** —— 2 つ以上のスライスが従う判断。ここがずれていると全部ずれる
2. **設計書の「判断の記録」** —— 却下案が書いてあるので、思考が最短で追える
3. **要求（USDM）の理由の列** —— なぜ必要かが変わっていないか
4. 実装は最後。 **読むのは差分ではなく入口**（設計書に書かれた関数）

**実装の差分を先に読まない。** 差分は「何が起きたか」しか語らず、
「なぜそう決めたか」を語らない。追いつけない人が最初に落ちる罠。

## 既読地点の扱い

- 状態は `.steering/last-reviewed`（コミットハッシュ 1 行）に置く。
  会話ではなく環境に置くので、セッションが切れても失われない
- `.steering/` は gitignore 対象。 **既読地点は人ごと・環境ごとに独立する**
  （共有すると「誰が読んだか」が混ざって意味を失う）
- 更新するのは **ダイジェストを出した後だけ** 。出す前に更新すると、
  読んでいないものを既読にしてしまう
- ファイルが無い場合は「まだ一度も追いついていない」。直近 20 コミットを見る

## いつ使うか

| 状況 | 打つもの |
|---|---|
| しばらく席を外していた | `/catchup` |
| 何をレビューすればいいか分からない | `/catchup`（読む順が出る） |
| 反復が何本か進んで全体像が怪しい | `/catchup` → `/status`（判断 → 現在地の順） |
| 特定の地点からの差分が見たい | `/catchup <ref>` |

`/status` との違い —— `/status` は **いまどこにいるか** （成熟度・充足・負債）、
`/catchup` は **何が決まったか** （判断の履歴）。両方あって初めて追える。

## ツール

前置コマンドはプロファイルの「`.claude/tools/` の Python ツール実行」。

```
<ツール実行コマンド> .claude/tools/build_digest.py            # 未読のダイジェスト
<ツール実行コマンド> .claude/tools/build_digest.py --since <ref>
<ツール実行コマンド> .claude/tools/build_digest.py --mark     # 既読地点を HEAD に進める
```

終了コードは **未読の有無** を返す（0 = 追いついている、1 = 未読あり、
2 = エラー）。SessionStart フックが同じ判定を使い、未読が多いときだけ知らせる。

## やってはいけないこと

- **ダイジェストを出す前に `--mark` する**（読んでいないものが既読になる）
- 影響度をその場の感覚で並べ替える（判定はツールが持つ。変えるならツールを直す）
- ダイジェストに **推測で要約を書く** —— 1 行要約は実際に読んだ文書からだけ書く
- `/catchup` を承認の場にする（止まるべき判断は `/iterate` の停止例外の領分）
- 既読地点をコミットする（`.steering/` は環境ごと）
