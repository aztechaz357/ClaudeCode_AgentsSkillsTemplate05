# 骨組みスキル（walking-skeleton）

**骨組み = 入口から出口まで通る、考えられる限り最も薄い 1 本の経路。**
機能はほぼ空でよい。通っていることが価値。

このスキルはプロジェクトに 1 回だけ使う（`/skeleton`）。
以降のスライスはこの骨組みに肉を付ける形で足す。

## なぜ最初にこれをやるか

骨組みが無いまま機能を積むと、最後に「配線」という最大の未知が残る。
そこで初めて設計の破綻・環境の不備・想定の誤りが噴出し、
それまで作った部品ごと作り直しになる。 **未知は最初に潰す。**

骨組みが通った時点で得られるもの:

- 実行できるコマンドが 1 つある（動作確認の手段が手に入る）
- E2E テストが 1 本ある（以降すべての反復がこれで守られる）
- 環境の不備（依存・パス・権限・エンコーディング）が全部露出済み
- 「動くもの」があるので、以降は差分で考えられる

## 骨組みの選び方

`docs/concept.md` の「典型シナリオ」から、 **最も短い 1 本** を選ぶ。

判定基準:

- [ ] 入口（CLI 引数・関数呼び出し・HTTP リクエスト）がある
- [ ] 出口（標準出力・戻り値・レスポンス・ファイル）がある
- [ ] 入口から出口まで、実際のコードが呼ばれて繋がっている
- [ ] 中身の処理は **ほぼ何もしない** （固定値を返すだけでよい）

**良い骨組みの例**:

| プロジェクト | 骨組み |
|---|---|
| CSV 集計ツール | `tool count sample.csv` → `3 行` と出る（実際にファイルを読む。集計は行数だけ） |
| Web API | `GET /health` → `{"status":"ok"}`（フレームワーク起動・ルーティング・JSON 返却が通る） |
| データ変換パイプライン | 1 レコードを読み、そのまま書き出す（変換なし） |
| 対話 CLI | 入力を 1 回受けて、固定の応答を返して終了する |

**悪い骨組みの例**:

- 「domain 層のエンティティを定義する」（出口が無い。動かない）
- 「設定ファイルの読み込みを作る」（入口も出口も利用者に見えない）
- 「集計ロジックを正しく実装する」（薄くない。骨組みの後でよい）

## 手順

### 1. 骨組みを 1 文で宣言する

`docs/backlog.md` の「完走の定義」に書く。書けないなら
`docs/concept.md` の典型シナリオが具体的でないので、そこへ戻る。

```
完走の定義: `<コマンド>` を実行すると、<入力> から <観測できる出力> が出る
```

### 2. S01 として最上段に置く

バックログのスライス表の S01 に置き、成熟度 `L0 未着手`。
**この時点で他のスライスも 1 行ずつ並べておく**（全体像が見えると
骨組みを薄く保ちやすい）。

### 3. E2E テストを先に書く（最重要）

宣言した 1 文をそのままテストにする。
**このテストが骨組みの定義であり、以降の全反復の安全網になる。**

- 置き場所: プロファイルの「統合テスト」パス
- 検証するのは **入口を叩いて出口を見る** ことだけ。内部構造を検証しない
- 実行し、失敗（Red）を確認する。この時点で失敗理由は「モジュールが無い」

### 4. 通す最小の実装を書く

薄いことを恐れない。次はすべて許される（L1 の条件）:

- 固定値を返す
- 1 ファイルに全部書く
- 層を分けない
- エラー処理をしない（落ちてよい）
- 設定をハードコードする

**やってはいけないこと**: 骨組みの段階で層を切る・契約を定義する・
設定機構を作る。それは L3 の仕事で、今やると骨組みが通る前に日が暮れる。

### 5. 実際に動かす

テストが緑になっただけでは完走ではない。 **プロファイルの動作確認
コマンドで実物を動かし、出力を目で確認する** 。その出力をスライス文書の
「実績」に貼る（推測で書かない。絶対ルール 7）。

### 6. 手抜きを記録する

ステップ 4 で許された手抜きを、すべて `docs/backlog.md` の負債表と
スライス文書の「残した手抜き」に書き出す。 **ここが後の
`/refactor` の入力になる** 。書かなければ手抜きは規約違反になる。

### 7. 記録してコミットする

- `docs/usdm/src/S01-<name>.html`（要求）と `docs/slices/S01-<name>.md`
  （設計・実績・手抜き）を作る（`slice-definition` のテンプレート）
- バックログの S01 を `L1 動く` に、「骨組み」を「通った（S01・日付）」に更新
- コミット（接頭辞 `骨組み:`）

## 完了条件

- [ ] E2E テストが 1 本あり、緑である（テスト先行で書いた証跡がある）
- [ ] プロファイルの動作確認コマンドで実物が動き、出力を貼った
- [ ] `docs/backlog.md` の「骨組み」が「通った」になっている
- [ ] 残した手抜きが負債表に記録されている
- [ ] コミット済み

## 骨組みが通らないとき

| 症状 | 対処 |
|---|---|
| 依存・環境が足りない | 環境の整備を先にやる。これも骨組みの一部（記録に残す） |
| 骨組みが半日で通らない | 薄くない。固定値を返すだけまで削る |
| どこから手を付けるか分からない | 出口（観測できるもの）から逆算する。出口 → 入口の順に決める |
| 設計を決めないと書けない気がする | それは L3 の関心。今は 1 ファイルに書いてよい |
