# 現状設計書 更新スキル

フェーズごとの設計書（proposals）が「これから作るもの」を書くのに対し、
現状設計書は「今あるもの」を書きます。このスキルは、現状設計書を実装と
同期させるためのガイドです。

## 対象文書と役割分担

**実際のファイル構成はプロファイルの「ドキュメント構成」表を正とする** 。
クリーンアーキテクチャを前提とした一般形は次のとおり:

| 文書 | 内容 | 更新タイミング |
|---|---|---|
| 全体概要（architecture 相当） | 文書マップ・レイヤー表・全体コンポーネント図・全体の決定事項 | 層構成・文書構成レベルの変化時のみ |
| domain 層設計書 | 契約（インタフェース）とエンティティ。クラス図 | 契約の追加・変更時 |
| application 層設計書 | ユースケース。シーケンス図 | ユースケース・サービスの変更時 |
| infrastructure 層設計書 | 契約→実装の対応表・横断方針 | 実装クラスの追加・変更時 |
| presentation 層設計書 | UI・入出力・表示 | 画面・CLI フロー・表示の変更時 |
| Composition Root 設計書 | 配線規則と設定解決 | 配線・設定の変更時 |

- プロファイルで **凍結指定された文書は絶対に更新しない**
- ロードマップ表の場所もプロファイル参照（行追加・ステータス更新はそこで）

## 更新の原則

1. 構造に影響する変更（クラス・レイヤー・依存の追加/変更）を実装したら、
   **同じ作業の中で** 該当レイヤー文書の図と表を更新する
2. 各レイヤー文書は「責務一覧・図・設計上の決定」に絞る。経緯・却下案・
   テスト観点の詳細は設計書（proposal）へのリンクで済ませ、
   全文転記しない（肥大化防止）
3. 記載内容は必ずソースコードと突き合わせる。クラス名・シグネチャを
   推測で書かない
4. Mermaid 図は英語識別子に日本語の意味を併記し、`.claude/tools/` の
   図検証ツールで構文検証する

## 実装完了時の反映手順

1. 実装済み設計書（`docs/design/proposals/P##-*.md`）を読み、
   「位置づけ（レイヤー配置）」の表から影響レイヤー文書を特定する
2. 各レイヤー文書の図（クラス図・シーケンス図・フロー図）と表に、
   追加・変更されたクラスを反映する（詳細ガイド: ./guide.md）
3. 設計書冒頭を「✅ 実装済み・反映済み」に更新する
4. 要求仕様書の受け入れ条件を統合テスト結果に基づき `[x]` に更新する
5. ロードマップ表のステータスを ✅ に更新する
6. 変更した図をすべて構文検証する

> この手順は doc-syncer エージェントのチェックリストと同一。エージェントに
> 一括委譲する場合は doc-syncer を起動する（手順の正を二重化しないこと）。

## テンプレート

新しいレイヤー文書・大きな節を追加する場合の構成: ./template.md
（既存文書の更新では既存の構造を維持し、テンプレートに作り変えない）
