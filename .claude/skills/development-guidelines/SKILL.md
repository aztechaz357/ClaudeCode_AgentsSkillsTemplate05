# 開発ガイドラインスキル

**コード・テスト・プロセスの規約の正は、このスキルの guides** です。
CLAUDE.md はプロジェクト固有値（プロファイル）と絶対ルールとルーティングだけを
持ち、規約の本文は持ちません。

## 正の所在

| 内容 | 正 |
|---|---|
| 言語・コマンド・パス・層構成・設計の型・安全機構 | `CLAUDE.md` のプロジェクトプロファイル |
| 絶対ルール | `CLAUDE.md` |
| **プロセスの進め方・成熟度・完了条件** | `agile-process` スキル（`SKILL.md` と `maturity.md`） |
| **層の分け方・依存ルール・配置** | `layered-architecture` スキル |
| コーディング・docstring・テストの書き方 | このスキルの `guides/implementation.md` |
| TDD・マイクロコミット・コミットメッセージ | このスキルの `guides/process.md` |
| リファクタリング（負債の返し方） | `refactoring` スキル |
| 文書の記法（Markdown・数式・図・マニュアル） | `writing-conventions` スキル |
| 工房レーン（`workshop/`）の作業 | `workshop` / `quick-tool` / `note-taking` スキル |

矛盾があればプロファイル（固有値）と絶対ルールが勝ち、guides を修正する。

## 最重要: 規約は成熟度で変わる

**このプロジェクトは「まず完走 → インクリメンタルに改善」で進む。**
規約をどこまで守るかは、対象スライスの成熟度で決まる。

| 規約 | L1 動く | L2 固い | L3 整った |
|---|---|---|---|
| テスト先行（Red 確認） | **必須** | **必須** | **必須** |
| 層の分離 | 不要（1 ファイル可） | 分かれている | 逆流ゼロ |
| docstring | 不要 | 公開する関数のみ | 全関数・クラス |
| エラー処理 | 不要（落ちてよい） | 想定内の失敗は結果値 | ＋読めるメッセージ |
| 失敗経路のテスト | 不要 | 必須 | 必須 |
| 文書同期 | スライス 1 枚 | 同 | ＋現状設計・マニュアル |
| コミット | **必須** | **必須** | **必須** |

**成熟度に関係なく常に必須なのは「テスト先行」と「コミット」と
「手抜きの記録」の 3 つだけ。** 残りは段階的に足していく。
完了条件の正は `agile-process/maturity.md` 。

## クイックリファレンス

### コード実装時

コーディング規約・docstring・テスト実装: ./guides/implementation.md

含まれる内容:
- 成熟度別に「今どこまで書くか」の判断
- 命名規則（契約・実装クラス・関数・定数）
- docstring 規約（役割 / 引数 / 戻り値、テスト 4 項目）
- エラー処理の型（L2 以上）
- テストコードの書き方（フェイク注入・ミラー構成・E2E との境界）

層の配置は `layered-architecture` スキルを正とする（ここでは重複させない）。

### プロセスの参照時

TDD・マイクロコミット・コミットメッセージ: ./guides/process.md

含まれる内容:
- 反復のフロー（骨組み → 反復 → リファクタリング）
- TDD サイクル（Red → Green → Refactor）と成熟度別の Green の基準
- マイクロコミットの粒度とコミットメッセージ規約（接頭辞の一覧）
- 記録の同期手順

## チェックリスト（実装完了前）

**成熟度に関係なく確認するもの**:

- [ ] テストを先に書いたか（Red を確認してから実装したか）
- [ ] 全テストが緑か（プロファイルのテストコマンド。骨組みの E2E を含む）
- [ ] 実際に動かして出力を確認したか（推測で書いていないか）
- [ ] 残した手抜きをスライス文書と `docs/backlog.md` の負債表に記録したか
- [ ] 作業のまとまりごとにコミットしたか（規約どおりのメッセージで）

**目標が L2 以上のとき追加**:

- [ ] 仕様 1 条につきテスト 1 本以上あるか
- [ ] 仮実装・ハードコードが残っていないか
- [ ] 逆流があれば負債表に記録済みか

**目標が L3 のとき追加**:

- [ ] 逆流ゼロか（アーキテクチャテストが緑か）
- [ ] すべての関数・クラスに docstring があるか
- [ ] `docs/design.md`・`docs/manual.md` を更新したか
