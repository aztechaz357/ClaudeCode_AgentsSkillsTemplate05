# 開発ガイドラインスキル

**コード・テスト・プロセスの規約の正は、このスキルの guides** です。
CLAUDE.md はプロジェクト固有値（プロファイル）と絶対ルールとルーティングだけを
持ち、規約の本文は持ちません。

## 正の所在

| 内容 | 正 |
|---|---|
| 言語・コマンド・パス・層構成・家風・安全機構 | `CLAUDE.md` のプロジェクトプロファイル |
| 絶対ルール（7 項目） | `CLAUDE.md` |
| コーディング・docstring・テストの書き方 | このスキルの `guides/implementation.md` |
| TDD・マイクロコミット・コミットメッセージ・設計同期 | このスキルの `guides/process.md` |
| 文書の記法（Markdown・数式・図・マニュアル） | `writing-conventions` スキル |
| 工房レーン（`workshop/`）の作業 | `workshop` / `quick-tool` / `note-taking` スキル |

矛盾があればプロファイル（固有値）と絶対ルールが勝ち、guides を修正する。
このスキルの guides は **本開発レーン** を前提とする。工房レーンで
適用されるのは「テスト先行」と「コミット」だけで、層構成・設計同期・
統合テストは適用されない。

## クイックリファレンス

### コード実装時

コーディング規約・docstring・テスト実装: ./guides/implementation.md

含まれる内容:
- レイヤー別の配置規則と import 制約（クリーンアーキテクチャ）
- 命名規則（契約・実装クラス・関数・定数）
- docstring 規約（役割 / 引数 / 戻り値、テスト4項目）
- フェイルソフト / フェイルクローズの実装パターン
- テストコードの書き方（フェイク注入・ミラー構成）

### プロセスの参照時

TDD・マイクロコミット・設計同期・文書規約: ./guides/process.md

含まれる内容:
- 開発の全体フロー（要求仕様書 → 設計書 → TDD → 統合テスト）
- TDD サイクル（Red → Green → Refactor）の運用
- マイクロコミットの粒度とコミットメッセージ規約
- 設計書との同期手順
- Markdown / Mermaid 規約と検証コマンド

## チェックリスト（実装完了前）

- [ ] テストを先に書いたか（Red を確認してから実装したか）
- [ ] 全テストが緑か（プロファイルのテストコマンドで確認）
- [ ] 依存ルール違反がないか（アーキテクチャテストがあれば実行）
- [ ] すべての関数・クラスに docstring（役割 / 引数 / 戻り値）があるか
- [ ] テスト docstring に4項目（テスト対象・入力・期待値・理由）があるか
- [ ] 作業のまとまりごとにコミットしたか（規約どおりのメッセージで）
- [ ] 構造に影響する変更なら現状設計書・リファレンスを更新したか
