# マニュアル（取扱説明書）の規約

**マニュアルは 8 点セットの 8 番目。毎スライスで更新する。**
「使い方が分からない機能」は存在しないのと同じ。

## 必須であって任意ではない

- マニュアルの更新は **どの成熟度でも完了条件に含まれる** 。
  「L3 で書く」「最後にまとめて書く」は **禁止** ——
  後でまとめて書いた文書は、実物とずれた嘘の文書になる
- 代わりに L1 では薄くてよい（下の「成熟度別の深さ」）。
  省くのは分量であって、節そのものではない
- **実装が動いた直後に、実際に動かしながら書く**

## 構成（この順で固定）

冒頭に **共通 3 節** 、その下にスライスごとの節を並べる。

```markdown
# {プロジェクト名} マニュアル

## 1. 環境構築
## 2. 実行方法
## 3. テストの実行方法

## S01 {スライス名}
## S02 {スライス名}
...
```

### 共通 3 節（骨組みで作り、以降の反復で維持する）

| 節 | 書くこと | 出典（推測しない） |
|---|---|---|
| `## 1. 環境構築` | 依存のインストール手順と、入ったことを確かめる 1 コマンド | プロファイルの「依存の同期 / 追加」 |
| `## 2. 実行方法` | 実物の起動コマンドと、実際に得た出力 | プロファイルの「動作確認」 |
| `## 3. テストの実行方法` | 全体・範囲指定・統合テストのコマンドと実測件数 | プロファイルの「テスト」各行 |

**3 節ともコマンドをコピーすれば動くこと** を、書いた本人が実行して確かめる。
コマンドは `CLAUDE.md` のプロファイルから写す（記憶で書かない）。

環境構築には、最低限これを書く:

- 必要なランタイムとバージョン（プロファイルの「主言語 / バージョン」）
- 依存の取得コマンドと、その実行例（実際の出力つき）
- 動いたと判断できる確認コマンド 1 つ（「入った」の定義）

### スライスごとの節

見出しに **`S##` を必ず含める** （`check_deliverables.py` がこの文字列で
節の存在を確認する）。中身は次の 4 つ。

1. **何ができるか** —— 1〜2 行
2. **最小の実行例** —— コピーして貼れば動く最短のもの ＋ **実際の出力**
3. **引数の意味** —— 単位付きの表。物理量は単位を必ず書く
4. **落とし穴** —— 「症状 → 原因 → 対処」の表。実際に踏んだものを残す

## 成熟度別の深さ

| 成熟度 | スライスの節に入れるもの |
|---|---|
| **L1 動く** | 何ができるか ＋ 最小の実行例（実測の出力）＋ 引数の表 |
| **L2 固い** | ＋ 落とし穴（症状 → 原因 → 対処） |
| **L3 整った** | ＋ 結果の読み方（戻り値の構造）・既知の制限 |

## コード例は実行して出力を確認する

**出力を推測で書かない。** 実際に実行し、得られた出力をそのまま貼る。

Python プロジェクトでは、コード例を ` ```python ` 、その出力を直後の
言語指定なし ` ``` ` に書くと検証ツールが自動で照合する。

```
<プロファイルの「.claude/tools/ の Python ツール実行」コマンド> .claude/tools/check_doc_examples.py docs/manual.md
```

このツールは ` ```python ` ブロックを実際に実行し、直後の出力ブロックと
照合する。 **マニュアルを更新したら必ず実行する。**
出力に `N compared` が表示されるので、 **照合された数が例の数と一致して
いることを確認する** （一致しないなら書式がずれていて、実行しただけで
照合されていない）。

Python 以外の言語のプロジェクトでは、同等の照合手段を用意するまで
**コード例を手で実行し、その出力を貼る** （推測で書かないことは同じ）。

> 実例: このツールを導入した時点で、既に書いてあった手書きの期待出力
> 2 箇所が実際の出力と食い違っていた。人間もエージェントも出力を
> 正確には覚えていない。

## 工房レーンでの簡易版

工房のツール（`workshop/tools/<name>/README.md`）は README 1 枚で完結する。
共通 3 節は要らず、 **何ができるか・最小の実行例・引数の表・落とし穴**
の 4 つを最低限とする（`quick-tool` スキルのテンプレートがこの形）。

- 実行例の出力は **実際に動かして貼る** —— これは工房でも必須。
  推測で書いた出力は嘘になる
- 「結果の読み方」「既知の制限」は、書けるなら書く。
  `/promote` で反復開発レーンへ昇格させるときに必須へ引き上げ、
  そのとき `docs/manual.md` の `## S##` 節へ移す
