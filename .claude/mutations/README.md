# 変異仕様（`.claude/mutations/`）

`mutate.py` に渡す **変異仕様** （テストの有効性を確かめるために実装へ
意図的に入れる誤り）を、スライスごとの JSON として置く場所です。

テストが緑であることは「テストが有効であること」を意味しません。
実装を壊してもテストが通るなら、そのテストは何も守っていません。
ここに仕様を残しておくと、後のスライスで同じ検査を再実行できます。

## ファイル名

`S##-<対象>.json`（例: `P01-validator.json`）。1 ファイル = 1 つの検査単位。

## 書式

`example.json` を参照。1 要素が 1 つの変異で、キーは次のとおり。

| キー | 必須 | 意味 |
|---|---|---|
| `file` | ✅ | 変異を加えるファイル（リポジトリルートからの相対パス） |
| `find` | ✅ | 置換前の文字列（実装中に 1 箇所だけ現れる形にする） |
| `replace` | ✅ | 置換後の文字列（もっともらしい誤りにする） |
| `expect` | | 落ちるべきテスト名の一部。指定すると、別のテストで落ちた場合に警告が出る |
| `label` | | 出力に表示する説明（省略時は `find` の先頭） |
| `count` | | 置換する出現回数（既定 1。0 で全て） |

## 実行

```
<プロファイルの「.claude/tools/ の Python ツール実行」コマンド> .claude/tools/mutate.py --spec .claude/mutations/S##-<対象>.json
```

- `KILLED` = 変異を検出できた（テストが有効）
- `SURVIVED` = 変異を検出できなかった（ **テストの穴** 。テストを追加する）
- 終了コード: 0 = 全て KILLED / 1 = SURVIVED あり / 2 = 引数・環境のエラー

対象ファイルは、テストが落ちても中断されても必ず元へ戻ります。

## どんな変異を書くか

「もっともらしい誤り」を選ぶ（実装を無意味に壊しても意味がない）。

- 符号・演算子の取り違え（`+` / `-` 、 `and` / `or` ）
- 境界値のずらし（`<=` → `<`）
- 係数・単位の掛け忘れ
- 状態更新の順序入れ替え・更新漏れ
- 検証（フェイルクローズ）の条件をゆるめる
