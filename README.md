# ClaudeCode Agents / Skills テンプレート

Claude Code で開発を回すための、エージェント・スキル・コマンド・ツール一式
（`.claude/`）と、規約の雛形（`CLAUDE.md`）です。 **プロジェクト非依存** で、
固有の値は `CLAUDE.md` の「プロジェクトプロファイル」に集約します。

## 方針: まず完走 → インクリメンタルに改善

**完璧を積み上げません。** 端から端まで動く骨組みを最初に作り切り、
そのあと成熟度を 1 段ずつ上げていきます。

```
ゴール定義 → バックログ → 骨組み（完走）→ 反復 ⇄ リファクタリング → 完成
```

| 成熟度 | 一言 | テスト | 許されること |
|---|---|---|---|
| `L1 動く` | 使える | E2E 1 本 + 芯のユニット | 仮実装・ハードコード・1 ファイル集約（ **記録必須** ） |
| `L2 固い` | 壊れない | 受け入れ条件ごとに 1 本以上 | 構造の不揃い・文書の未整備 |
| `L3 整った` | 渡せる | 全緑 + 回帰 | なし（他人に渡すときだけ到達する） |

- **テストは省きません** —— 省くのは前工程の文書と構造だけ。
  L1 でもテスト先行（Red 確認）と E2E 1 本は必須
- **手抜きは許し、隠すのは許しません** —— 仮実装は負債表に書けば
  正式に許可され、`/refactor` の工程で返します
- **クリーンアーキテクチャは要求しません** —— レイヤードで、守るルールは
  「逆流禁止」の 1 つ。必要になった層だけ後から依存性逆転へ育てます
- **自分だけが使う道具は L2 で完成** —— L3 は他人に渡すためのレベルです

## 2 本の道

| | 工房レーン | 反復開発レーン |
|---|---|---|
| 向くもの | 思いついた小さなツール・ノート | 腰を据えて作るプロダクト |
| 前工程 | なし | ゴールと完走の定義 → バックログ |
| 単位 | ツール 1 本 / ノート 1 本 | 縦切りスライス（S##） |
| 文書 | `README.md` 1 枚 | スライス 1 枚（条件 3 行 + 設計 5 行） |
| 構造 | 1 ディレクトリ完結 | レイヤード（L1 では 1 ファイル可） |
| テスト | 必須（テスト先行） | 必須（テスト先行 + E2E） |
| 入口 | `/tool` `/note` `/workshop` | `/backlog` `/skeleton` `/iterate` `/refactor` |
| 所要 | 数十分 | 1 反復あたり半日以内 |

工房で省くのは前工程と構造であって、テストではありません。
育ったツールは `/promote` で反復開発レーンへ上げられます。

## 使い方

```
1. .claude/ と CLAUDE.md を対象プロジェクトへコピーする
2. Claude Code で /setup-project    … プロファイルの {} を実物の値で埋める

   ＜軽い方＞
3. /tool 2つの CSV の差分を出したい  … テスト付きのツールが workshop/ に 1 本できる
4. /note 調べたこと                  … workshop/notes/ に残る
5. /workshop search <語>             … 過去に作ったものを探す

   ＜重い方＞
6. /backlog init                    … ゴールと完走の定義 → スライス 3〜8 本
7. /skeleton                        … 骨組みを作り切る（動くものが手に入る）
8. /iterate                         … スライスを 1 本ずつ育てる（★繰り返す）
9. /refactor                        … 負債がたまったら返す
10. /improve-process                … 数反復ごとにプロセス自体を改善する
```

反復開発レーンを始めるときは、`CLAUDE.md` に `{` が残っていないこと
（エージェントがコマンドやパスを推測し始めます）。工房レーンだけなら、
プロファイルの「コマンド」「ディレクトリ構成」が埋まっていれば動きます。

厚い経路（要求仕様書と設計書を分けて書く `/add-feature`）も残していますが
**既定ではありません** 。使うのは不可逆な操作・外部公開・安全機構・
データ形式が絡むスライスだけです。

## 中身

| 場所 | 内容 |
|---|---|
| `.claude/commands/` | 反復開発: `/backlog` `/skeleton` `/iterate` `/refactor` `/add-feature` ／ 工房: `/tool` `/note` `/workshop` `/promote` ／ 共通: `/setup-project` `/check-docs` `/review-docs` `/improve-process` |
| `.claude/agents/` | 指揮・調査・実装・整理（`refactorer`）・実行・検証・文書のサブエージェント ＋ 工房の `tool-smith` `note-keeper` |
| `.claude/skills/` | プロセスの正（`agile-process`）・骨組み・スライス定義・リファクタリング・レイヤード構造・ゴール定義・規約・記法・steering・工房・ツール新設 |
| `.claude/tools/` | 図・番号・マニュアル例・core 無変更・変異テストの検証スクリプト ＋ 工房の雛形生成と索引 |
| `.claude/templates/` | 工房の雛形（ツールの README・実装・テスト、ノート） |
| `.claude/hooks/` | ハーネスが必ず走らせるフック（保護パスの防護・Markdown 検証・通知・未コミット警告・セッション開始時の状況注入） |
| `.devcontainer/` | Claude Code をサンドボックスで動かす開発コンテナ（コンテナ + 送信ファイアウォール + Claude Code サンドボックスの 3 層） |
| `CLAUDE.md` | プロジェクトプロファイル・絶対ルール・ルーティング（規約の本文はスキル側） |
| `workshop/` | 工房の成果物。このリポジトリ自身の作例（ツール 2 本・ノート 3 本）が入っている。対象プロジェクトへコピーするのは `.claude/` と `CLAUDE.md` だけなので、作例が持ち込まれることはない |

設計思想と開発フローの詳細は `.claude/README.md`、
プロセスの完了条件は `.claude/skills/agile-process/maturity.md` を参照。

## 前提環境

- Claude Code
- Windows / PowerShell 5.1 を想定したツールを含む（`.ps1`。Linux では
  `pwsh` に symlink すれば動く —— 開発コンテナが自動で行う）
- 図の検証: Node.js（mermaid-cli）・Graphviz・PlantUML（使う図の分だけ。
  図が必要になるのは L3 なので、最初は無くてよい）
- `.py` ツールを使う場合は Python 実行環境

上記を揃えるのが面倒なら、 **開発コンテナを使うのが早い** 。
Docker があれば `Reopen in Container` だけで、ツールが揃い、
かつ AI がホストを壊せず外部へ勝手に通信できない状態になる
（詳細は `.devcontainer/README.md`）。
