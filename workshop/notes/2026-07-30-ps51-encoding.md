# PowerShell 5.1 の文字コード事故

## 要点

- `.ps1` は **ASCII だけで書く** 。BOM なし UTF-8 を 5.1 は ANSI として読む
- 日本語のコメントは次の行を巻き込んで壊す。説明は README 側に書く
- ファイル入出力は `Get-Content` / `Set-Content` ではなく
  `[System.IO.File]::ReadAllText` / `WriteAllText` ＋ UTF8Encoding($false)

## 背景 / きっかけ

`.claude/tools/` の PowerShell ツールに日本語のコメントを入れたところ、
コメントの次の文が構文エラーになった。工房レーンの雛形（`tool-main.ps1`）を
どう書くか決めるために、原因と回避策をまとめた。

## 中身

### なぜ壊れるか

Windows PowerShell 5.1 は、BOM の無い `.ps1` をシステムの ANSI コードページ
（日本語環境では CP932）として読む。UTF-8 で書いた日本語はバイト列として
解釈が狂い、コメント行の末尾にある改行までコメントの一部として飲み込まれる
ことがある。すると次の行が前の行の続きとして解析され、無関係な場所で
構文エラーになる。エラー位置が原因位置と一致しないので気づきにくい。

### 回避策

1. `.ps1` の中身は ASCII だけにする。日本語の説明は同じディレクトリの
   `README.md` に置く
2. 出力に日本語が要るときは、文字列をコードポイントから組み立てる:

```
$J = @{ Catalog = [string][char]0x5DE5 + [char]0x623F }
```

3. ファイルを読み書きするときは .NET を直接使う。`Get-Content` /
   `Set-Content` は既定が ANSI で、UTF-8 のファイルを壊す:

```
$text = [System.IO.File]::ReadAllText($path)
$enc  = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText($path, $text, $enc)
```

### 5.1 で他に無いもの

- `[System.IO.Path]::GetRelativePath` は .NET Core 2.0 以降。
  5.1（.NET Framework 4.x）には無いので、接頭辞を削る関数を自前で書く
- `&&` / `||` / 三項演算子 / `??` も無い。`;` と `if` で書く
