# Grep ツール（ripgrep）の glob と正規表現の落とし穴

## 要点

- `*.ps1` は **パス全体** に対して当たるので、サブディレクトリも拾う。
  階層を絞りたいときだけ `**/tools/**/*.ps1` の形にする
- ripgrep は grep ではないので `{` `}` はメタ文字。リテラルは
  `interface\{\}` のようにエスケープする
- 件数だけ欲しいときは `output_mode: count` 。本文を context に流し込まない

## 背景 / きっかけ

工房レーンのツールを追加したあと「`.claude/tools/` の PowerShell スクリプトが
何本あるか」を数えようとして、`*.ps1` がリポジトリ全体に当たることに
気づいた。同じ勘違いを繰り返さないように残す。

## 中身

### glob はパス全体に当たる

`*.ps1` はファイル名パターンではなくパスパターンとして扱われ、
リポジトリ全体の `.ps1` が対象になる。このリポジトリで数えるとこうなる。

```
Found 84 total occurrences across 16 files.
```

`tools` ディレクトリ配下だけに絞ると半分になる。

```
Found 46 total occurrences across 8 files.
```

絞り込みは `**/tools/**/*.ps1` のように、間に `**` を挟んだ形で書く。
`tools/*.ps1` と書くと、探索の起点からの相対で一致するものしか当たらない。

### 波括弧はエスケープが要る

ripgrep の既定は Rust の正規表現なので、`{` `}` は繰り返し回数の指定として
解釈される。リテラルとして探すならエスケープする。

```
interface\{\}
```

エスケープを忘れると「繰り返し指定が不正」として弾かれるか、
意図せず 0 件になる。0 件のときは **パターンの誤りをまず疑う** 。

### 出力モードの使い分け

| 目的 | `output_mode` |
|---|---|
| どのファイルにあるかだけ知りたい | `files_with_matches`（既定） |
| 何件あるか知りたい | `count` |
| 実際の行を読みたい | `content`（`-n` `-C` が効く） |

`content` は行がそのまま流れ込むので、当たりが多そうなときは先に
`count` で規模を見る。
