# port-check

指定ホストの TCP ポートに接続できるかを調べ、結果を終了コードで返す。
サーバーが起動し終わったかの確認や、待ち受けポートの取り違えの切り分けに使う。

## 1. 準備

不要（PowerShell 5.1 と .NET Framework だけで動く）。

## 2. 最小の実行例

```
powershell -NoProfile -File main.ps1 -Target 127.0.0.1 -Port 45871
```

開いている場合:

```
OPEN: 127.0.0.1:45871
```

閉じている場合（終了コード 1）:

```
CLOSED: 127.0.0.1:45871 (timed out after 300 ms)
```

引数が誤っている場合（終了コード 2）:

```
ERROR: -Port must be 1-65535 (got 0)
```

## 3. 引数

引数は表 1 のとおり。

表 1: port-check の引数

| 引数 | 必須 | 意味 | 既定値 |
|---|---|---|---|
| `-Target` | いいえ | 接続先のホスト名または IP アドレス | `127.0.0.1` |
| `-Port` | はい | 調べる TCP ポート番号（1〜65535） | なし（未指定は引数エラー） |
| `-TimeoutMs` | いいえ | 接続を待つ上限時間 [ms] | `1000` |

終了コードは 0 = 開いている / 1 = 閉じている・時間切れ / 2 = 引数エラー。

## 4. 落とし穴

実際に踏んだものを表 2 に挙げる。

表 2: port-check の落とし穴

| 症状 | 原因 | 対処 |
|---|---|---|
| 閉じたポートでも「connection refused」ではなく `timed out` と出る | ローカルのファイアウォールが拒否応答を返さずパケットを捨てている | 判定（終了コード 1）は正しいのでそのまま使う。速さが要るなら `-TimeoutMs 300` 程度まで下げる |
| 存在しないホスト名で `CLOSED` になる | 名前解決の失敗も接続失敗として扱っている | 括弧内のメッセージを見る。DNS 由来かどうかはそこに出る |

## 5. 既知の制限

- TCP のみ。UDP は調べられない
- 「開いている」は接続を受け付けたことだけを意味し、期待したサービスが
  動いているかは確認しない
- 1 回に 1 ポートのみ。範囲スキャンはしない（それが要るなら本開発レーンの話）
